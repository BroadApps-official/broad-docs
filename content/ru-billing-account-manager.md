# RU Billing: спешл оффер и A/B-тест — аккаунт-менеджеру

На этой странице два независимых сценария для аккаунт-менеджера. Первый —
подготовить **RU Billing Special Offer**. Второй — отдельно настроить
**A/B-тест в RU Billing**, только если команда действительно выбрала RU Billing
источником варианта.

Код приложения здесь не настраивается. Разработчику не нужен пароль от
платёжного кабинета — ему нужны точные ID, согласованные условия и заполненная
карточка из нужного раздела.

| Аккаунт-менеджер | Разработчик |
|---|---|
| выбирает точную запись приложения и среду | подключает значения к коду текущего приложения |
| проверяет продукт Special Offer в платёжном каталоге `nextgenwebapps` | выбирает RU-продукт только по `widgetTitle == "kupon"` |
| для примера 232 задаёт `kupon = true` в Adapty Remote Config | читает флаг из текущего ответа Adapty |
| при необходимости настраивает RU Billing A/B | читает вариант из подтверждённого источника |

## RU Billing Special Offer

Сначала убедитесь, что обычный RU Billing уже настроен по статье
[«RU Billing: карта и СБП»](./ru-billing.md): приложение и среда выбраны,
продукты заведены, СБП/карта и проверка оплаты работают. Ниже перечислены
только дополнительные действия для Special Offer.

Этот раздел нужен, когда после закрытия обычного paywall пользователь должен
увидеть отдельное предложение RU Billing. Эталон на этой странице — приложение
`232 Claude`: bundle `com.arm.232C1aude`, булевый флаг `kupon` и строка
платёжного каталога `nextgenwebapps` с
`widgetTitle == "kupon"`. В 232 эта строка возвращает
`monthly_12.99_nottrial` за 990 ₽. `kupon = true` всегда показывает Special
Offer, любое другое значение не показывает его. A/B-сегмент не добавляется как
второй gate.

> **Главное действие в кабинете.** До передачи задачи разработчику убедитесь,
> что платёжный каталог `nextgenwebapps` для bundle `com.arm.232C1aude`
> возвращает подписочную строку `widgetTitle == "kupon"`. Для 232 её
> `productId` равен `monthly_12.99_nottrial`, цена — 990 ₽.
> Затем убедитесь, что текущий paywall Adapty возвращает в Remote Config точное
> булево значение `kupon = true`.

### Что должно получиться

```text
Обычный paywall
└─ закрытие без успешной покупки или restore
   └─ текущий Adapty Remote Config: kupon == true?
      ├─ нет / нет поля / ошибка → главный экран приложения
      └─ да
         └─ запросить nextgenwebapps для com.arm.232C1aude
            └─ выбрать widgetTitle == "kupon"
               └─ monthly_12.99_nottrial → RU Billing checkout
                  ├─ подтверждённая оплата → Premium
                  └─ закрытие / неподтверждённая оплата → главный экран приложения без Premium
```

Наличие скидочного продукта само по себе не открывает второй экран. Команда
должна включить `kupon` в Adapty Remote Config, а платёжный каталог
`nextgenwebapps` — вернуть подписочную строку `widgetTitle == "kupon"`.
RU-продукт не выбирается из Adapty или App Store.

### Шаг 1. Найдите точное приложение

Откройте **Управление → Приложения** и найдите приложение по согласованному
идентификатору. Похожее название не является достаточной проверкой.

До дальнейших действий подтвердите:

- это нужное production- или test-приложение;
- выбран правильный активный платёжный провайдер;
- разработчик и тимлид подтвердили среду;
- изменения не затронут другое приложение.

Если в кабинете несколько похожих строк, не выбирайте «самую новую» или «самую
красивую». Попросите тимлида назвать точную запись.

### Шаг 2. Проверьте продукт в каталоге nextgenwebapps

В карточке выбранного приложения откройте платёжные продукты. Отдельный продукт
Special Offer должен попасть в каталог `nextgenwebapps` до передачи задачи
разработчику. Не переиспользуйте обычный тариф только потому, что у него
похожая цена.

Для 232 запрос каталога `nextgenwebapps` с
`bundleId=com.arm.232C1aude` должен вернуть `monthly_12.99_nottrial` за 990 ₽,
`widgetTitle == "kupon"` и `isForSubscription == true`. Разработчик не
сопоставляет эту строку с продуктом Adapty или App Store: он берёт её
`productId` и передаёт его в RU checkout.

Для каждого продукта проверьте:

- `widgetTitle == "kupon"` в каталоге `nextgenwebapps`;
- активен ли он;
- цену и валюту;
- разовая это покупка или подписка;
- период подписки или длительность Premium;
- доступные RU-способы оплаты: СБП и карта;
- не используется ли эта же запись другими приложениями.

Не меняйте общий продукт ради одного нового приложения. Если цена или период
должны отличаться, попросите создать отдельный product ID.

### Шаг 3. Включите флаг в Adapty Remote Config

В Adapty откройте paywall, ответ которого используется перед переходом в
Special Offer, и добавьте в его Remote Config:

```json
{
  "kupon": true
}
```

Значение должно быть булевым, не строкой `"true"` и не числом `1`. Разработчик
читает флаг только из текущего фактически полученного ответа Adapty. `false`,
отсутствующее поле или ошибка означают: не показывать Special Offer, открыть
главный экран приложения.

Никаких дополнительных правил показа не настраивайте. Remote Config
возвращает `kupon = true` — приложение показывает Special Offer;
возвращает что-либо другое — не показывает.

Не настраивайте и не заказывайте для этого сценария таймер, cooldown, дату
окончания или лимит повторных показов.

Команда должна заранее подтвердить только содержимое экрана:

- какие тексты, изображения, legal-ссылки и способы оплаты показывать.

### Шаг 4. Передайте разработчику карточку Special Offer

Скопируйте блок, заполните все строки и отправьте одним сообщением:

```text
RU Billing Special Offer

Точная запись приложения: 232 Claude
Bundle ID: com.arm.232C1aude
Среда: test / production
Adapty placement с Remote Config: основной paywall
Adapty Remote Config: kupon = true
Источник RU-продукта: nextgenwebapps paywallProducts
Параметр каталога: bundleId = com.arm.232C1aude
Условие выбора: widgetTitle == kupon, isForSubscription == true
Product ID из nextgenwebapps: monthly_12.99_nottrial
Цена и валюта: 990 ₽
Статус продукта: активен
RU-способы оплаты: СБП / карта

Правило показа: kupon = true → всегда показать; иначе не показывать
Таймер / cooldown / лимит показов: отсутствуют
Тексты и изображения:
Privacy Policy:
Terms of Use:

Кто подтверждает готовность backend:
Кто принимает тестовую сборку:
Дата запуска:
```

Не передавайте пароль от кабинета, секретный ключ платёжного провайдера,
пользовательские данные или финансовую выгрузку.

### Шаг 5. Проверьте Special Offer в тестовой сборке

Вместе с разработчиком проверьте:

1. обычный paywall открывается;
2. покупка и restore не открывают Special Offer;
3. при `kupon = false` или без поля открывается главный экран приложения;
4. при `kupon = true` после каждого подходящего закрытия загружается каталог `nextgenwebapps`;
5. для 232 по `widgetTitle == "kupon"` выбран `monthly_12.99_nottrial`, а не продукт Adapty или App Store;
6. СБП и карта открывают согласованный тестовый checkout;
7. возврат из браузера без подтверждения не выдаёт Premium;
8. закрытие Special Offer открывает главный экран приложения без Premium;
9. повторное закрытие paywall сразу снова открывает Special Offer без паузы;
10. в сценарии нет таймера, даты окончания или лимита показов.

Настоящую оплату не проводите без отдельного разрешения и согласованного
тестового сценария.

### Если Special Offer не работает

| Симптом | Что проверить аккаунт-менеджеру |
|---|---|
| Второй экран не появился | Текущий ответ Adapty и точное булево `kupon = true` |
| На экране нет цены | Возвращает ли `nextgenwebapps` для bundle 232 `monthly_12.99_nottrial`, 990 ₽ и `widgetTitle == "kupon"` |
| СБП или карта не видны | Провайдер, разрешённые способы оплаты и готовность backend |
| После браузера открылся Premium без оплаты | Немедленно остановить запуск и передать разработчику: Premium разрешает только подтверждённый backend-статус |

## RU Billing A/B-тесты

Этот раздел нужен только для сравнения двух или нескольких вариантов продукта
или оформления. Он не может добавлять второй gate показа Special Offer.
Приложение 232 всё равно принимает решение только по `kupon` из текущего
Adapty Remote Config.

Если A/B настраивается в Adapty, разные variation могут возвращать разные
значения Remote Config, но приложение не проверяет variation отдельно. Если
вариант назначает RU Billing/backend, он может выбрать продукт или оформление
уже разрешённого оффера, но не заменить собой `kupon`.

> **Менеджер не может определить готовность по кабинету.** В общей платформе
> готовое назначение вариантов есть только через Adapty. RU Billing/backend
> требует отдельной реализации в конкретном приложении. Перед созданием и
> запуском откройте разработчику инструкцию
> [«RU Billing: A/B-тесты для разработчика»](./ru-billing-ab-tests-developer.md)
> и получите заполненную карточку подтверждения.

### Шаг 1. Подтвердите источник варианта

До настройки кабинета задайте тимлиду один прямой вопрос:

> «Сегмент этого теста назначает Adapty или RU Billing?»

- обычные paywall-эксперименты платформы может назначать Adapty;
- RU Billing Experiment используется только если разработчик подтвердил, что
  код этого приложения получает вариант из RU Billing;
- один эксперимент нельзя независимо создать и в Adapty, и в RU Billing для
  одной аудитории: пользователь может получить разные варианты.

Если ответ не получен, RU Billing A/B-тест пока не создавайте.

### Шаг 2. Создайте эксперимент в RU Billing

Если разработчик подтвердил RU Billing experiment API, откройте
**Управление → Эксперименты → Новый эксперимент**.

Заполните:

1. **Приложение** — точная согласованная запись.
2. **Название** — понятная бизнес-цель теста.
3. **Код эксперимента** — стабильный код, согласованный с разработчиком.
4. **Статус** — до проверки оставьте неактивным.
5. **Дата и время начала** — согласованный момент запуска.
6. **Сегменты** — стабильные коды и понятные названия вариантов.

### Шаг 3. Опишите контроль и тест

Безопасная схема для Special Offer не меняет правило показа:

| Сегмент | Что видит пользователь |
|---|---|
| Контроль | Special Offer с контрольным продуктом или оформлением, если `kupon = true` |
| Тест | Special Offer с тестовым продуктом или оформлением, если `kupon = true` |

При любом значении, кроме булева `true`, оба сегмента не видят Special Offer.

Коды сегментов должен знать код приложения. Не переименовывайте их после
передачи разработчику без повторного согласования.

### Шаг 4. Передайте разработчику карточку A/B-теста

```text
RU Billing A/B Test

Точная запись приложения:
Среда: test / production
Источник варианта: RU Billing
Код эксперимента:

Контрольный сегмент — код и поведение:
Тестовый сегмент — код и поведение:
Распределение аудитории:
Событие показа варианта:
Целевая метрика:

Кто подтверждает готовность backend:
Кто принимает тестовую сборку:
Кто подтверждает запуск эксперимента:
Дата и время запуска:
Условие остановки:
```

Параметры самого Special Offer передавайте отдельной карточкой из первого
раздела. Так продуктовые настройки и настройки эксперимента не смешиваются.

### Шаг 5. Проверьте и запустите A/B-тест

До production-запуска вместе с разработчиком проверьте:

1. приложение получает вариант именно из RU Billing;
2. контроль и тест используют согласованные коды сегментов;
3. оба сегмента показывают Special Offer только при `kupon = true`;
4. контроль и тест видят свои согласованные продукты или оформление;
5. аналитика получает код эксперимента, сегмент и событие показа;
6. повторный запуск не меняет вариант неожиданно;
7. эксперимент остаётся неактивным до общего подтверждения.

После подтверждения разработчика и тимлида:

- активируйте эксперимент в согласованное время;
- откройте **Аналитика → Эксперименты**;
- убедитесь, что пользователи приходят в ожидаемые сегменты;
- не меняйте коды, продукты или трактовку сегментов посреди теста;
- остановку или продление согласуйте с владельцем эксперимента.

### Если A/B-тест не работает

| Симптом | Что проверить аккаунт-менеджеру |
|---|---|
| Все попали в один вариант | Статус эксперимента, распределение и коды сегментов |
| Пользователь видит не тот сценарий | Источник варианта и соответствие кода сегмента поведению |
| Аналитика пустая | Код эксперимента и событие показа, переданное разработчиком |
| Adapty и RU Billing дают разные варианты | Остановить тест и оставить один подтверждённый источник |
