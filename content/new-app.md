# Новое приложение с агентом

Маршрут для нового приложения компании, которое вы делаете с Claude или Codex. Учебный [BroadStart](./getting-started.md) нужен, чтобы увидеть, как код
платформы связан с экраном; основой нового приложения он не является.

## Что отправить агенту

Откройте агента в папке нового приложения и отправьте одно сообщение:

```text
Сделай iPhone-приложение <номер и название> на BroadApps iOS Platform.
Инструкция для агента: https://broadapps-ios-docs.nkhsnv.chatgpt.site/llms.txt
Kaiten: <ссылка на карточку>.
Дизайн: <ссылка на Figma> (открой в моём браузере, MCP не нужен) или no-code.
Backend: <ссылка на документацию>.
Сначала предложи поставить правила и скиллы BroadApps, затем начни с проверки
источников (preflight) и остановись с отчётом.
```

Всё остальное агент найдёт сам: этапы, шаблон плана и версии модулей. Данные
аккаунта (bundle, ключ Adapty, ссылки PP/ToU) он берёт из Kaiten. Секретные
токены, например админский токен backend, передайте отдельно — агент хранит их вне git.

## Backend уже есть в другом приложении

Если новое приложение использует работающий backend компании, отправьте агенту:

```text
Сделай iPhone-приложение <номер и название> на BroadApps iOS Platform.
Инструкция для агента: https://broadapps-ios-docs.nkhsnv.chatgpt.site/llms.txt
Kaiten: <ссылка на карточку>
Дизайн: <ссылка на Figma> — открой в моём браузере, MCP не нужен.
Backend: уже работает в приложении компании <номер> — <ссылка на репозиторий>; изучи там реальную работу с backend и выпиши контракт. OpenAPI: <ссылка, если есть>. Код пиши по правилам платформы, старую архитектуру и хардкод референса не переноси. Адрес backend, токены и данные Adapty нового приложения из референса не копируй — спроси.
Сначала предложи поставить правила и скиллы BroadApps, затем проверь источники (preflight) и остановись с отчётом и вопросами.
```

Агент прочитает репозиторий референса без правок, проследит реальные запросы,
выпишет их контракт и сверит с доступной документацией backend. О том, чего
источники не подтверждают, спросит до реализации зависимой функции. От вас
нужны ссылка на актуальный репозиторий, ответы на вопросы и секреты отдельно,
вне git и отчётов.

| Видите | Скажите агенту |
|---|---|
| Переносит старую архитектуру или зашивает продукты из референса | «Оставь только подтверждённое поведение. Реализуй его через компоненты платформы; контент бери с backend, продукты — из Adapty». |
| Взял адрес backend или токен референса | «Отметь `BLOCKED`. Спроси адрес и доступ для нового приложения; чужие значения удали». |
| Пишет код по найденному endpoint без подтверждения | «Сверь его с OpenAPI или владельцем backend. До подтверждения останови зависимую функцию». |

## Правила и скиллы компании для агента

Первым делом агент покажет список и спросит «Поставить?». После вашего «да» он
установит в свой Claude или Codex:

| Что | Зачем |
|---|---|
| Правила разработки BroadApps | Агент сразу знает правила компании: пейвол, плейсменты, ATT, iPad, вёрстку |
| Скилл `broadapps-new-app` | Этапы с остановками и что делать, пока нет аккаунта |
| Скилл `broadapps-figma` | Читает Figma в вашем браузере и сам выгружает картинки в 6x |
| Скилл `broadapps-ipad-check` | Проверяет экраны на iPad и iPhone SE, как App Review |

Правила ставятся одним блоком и обновляются на месте тем же скриптом
([AgentKit](https://github.com/BroadApps-official/broad-platform-integration/tree/main/AgentKit)).

## Как пойдёт работа

Агент делает один этап и останавливается. Следующий начинается после вашего
подтверждения.

| Этап | Что делает агент | Где остановится |
|---|---|---|
| 0. Проверка источников | Читает Kaiten, дизайн, backend и версии платформы; файлы не меняет | Отчёт READY / BLOCKED |
| 1. План | Пишет `Documentation/AppIntegrationPlan.md`, без кода | «НУЖНА ПРОВЕРКА ПЛАНА» |
| 2. Каркас | iPhone-проект, модули платформы, [дизайн-система](./layout.md), точки входа | «НУЖНА ПРОВЕРКА КАРКАСА» |
| 3. Функция | Одна функция целиком: экран → данные → результат | «НУЖНА ПРОВЕРКА ФУНКЦИИ» |
| 4. Поведение | Ошибки, пустые ответы, повторные нажатия, восстановление | Отчёт |
| 5. Внешний вид | Каждый экран сравнивается с макетом | Отчёт |
| 6. Передача | Сборки, ограничения и шаги для QA | Итог |

Фраза «НУЖНА ПРОВЕРКА …» в ответе агента — сигнал проверить результат и ответить
«да» или написать правки. Чего не хватает, агент
помечает `BLOCKED` и продолжает независимую работу. Экраны, endpoint и product ID
он не придумывает.

Готовые промпты для каждого этапа:
[AgentPromptPack](https://github.com/BroadApps-official/broad-platform-integration/blob/main/Documentation/AgentPromptPack.md).

## Figma или no-code

| | По Figma | No-code |
|---|---|---|
| Как понять | В карточке Kaiten нет метки `no-code` | В карточке есть метка `no-code` |
| Источник экранов | Кадры Figma | Макет, который разработчик собирает с агентом в Claude Design или Pencil |
| Экрана нет в источнике | `BLOCKED`, агент не дорисовывает | Сначала собрать макет, потом код |

## Экраны по Figma

- Агент спросит, с какого раздела начать — онбординг и пейвол, основная часть или
  настройки, — и попросит ссылки на кадры Figma этого раздела.
- Figma агент открывает в вашем браузере, где вы вошли в аккаунт. MCP не нужен:
  шрифты, отступы и цвета он читает на панели свойств справа.
- Иконки и фоны агент выгружает из Figma сам в 6x и кладёт в ассеты.
- Кадр «rate us» рядом с онбордингом — отдельный экран после успешной генерации, а
  не слайд онбординга.
- Логику маршрута первого запуска, онбординга и пейвола агент берёт из
  [BroadUIFlows](./broad-ui-flows.md), а экран рисует по макету.

Подробности этапов — в [создании приложения](./app-creation.md#работа-с-агентом).

## Аккаунта ещё нет

Метка «Жду аккаунт» в Kaiten: нет ключа Adapty, продуктов и ссылок PP/ToU. Работу не
останавливаем. Агент спросит, какое похожее приложение компании взять за образец (с
теми же экранами, например с токенами), — выбираете вы. Он временно берёт данные
образца и помечает их `TEMPORARY`. Перед выпуском значения заменяются данными из Kaiten.

Пока используются временные данные, экран показывает настоящие товары похожего
приложения: их цену, название и количество из Adapty, StoreKit и сервера. Числа и
названия тарифов в макете Figma — пример оформления, их не переносят в приложение.

## Как проверять покупки

> [!IMPORTANT]
> **TestFlight и доступа к кабинетам Adapty и App Store Connect у разработчиков нет** —
> всё у аккаунт-менеджеров. Покупку за реальные деньги агент не проводит.

- В Debug через локальный `.storekit` можно купить всё, что продаёт приложение:
  подписку на основном пейволе, спецоффер и пакеты токенов, включая товары
  плейсмента `tokens`. Деньги не списываются. Агент сам запускает приложение из
  Xcode (Run) и покупает каждый тип: видит лист оплаты, завершает покупку и
  проверяет, что доступ или баланс обновился. Если сервер не принял тестовую
  покупку, агент сообщает код ответа и что требуется от backend, без выдуманного
  начисления. Запуск через `simctl` не подключает `.storekit`: тарифов нет и
  купить нельзя. Если вы уже запустили Xcode сами, агент не нажимает в вашей сессии.
- В `.storekit` должны быть **все** эти товары из Adapty, с ценами как в App Store.
  Имя товара в файле заполните как в App Store; на пейволе показывайте название
  по периоду подписки («Yearly», «Monthly», «Weekly») или количеству токенов
  («2000 Tokens»). Количество берите из каталога сервера, а если его там нет —
  из начала ID (`50_Tokens_9.99` → 50), только для надписи. С BroadUIFlows 7.0.0
  готовые экраны показывают эти названия со встроенными текстами `.standard`,
  `.english` и `.russian`. В свои тексты добавьте названия; до этого поведение
  останется прежним. На 6.5.0 собирайте названия сами.
  Adapty показывает только товары, которые есть в файле: не хватает одного — на
  пейволе молча становится меньше вариантов. Агент проверяет файл скриптом и
  смотрит, что он не красный в схеме. В Debug локальный StoreKit должен быть
  подключён и к покупке подписок, и к покупке токенов; в Release покупки идут
  через Adapty.
- Плейсменты, продукты и Remote Config (`special_offer`, задержка крестика) меняет
  аккаунт-менеджер — агент подскажет, что у него попросить.

## Проверка на iPad

Приложения только для iPhone, но App Review смотрит их и на iPad: там приложение
открывается в окне режима совместимости — кнопки окна слева сверху, окно выше любого
iPhone. Агент проверяет каждый экран на iPad-симуляторе и iPhone SE: тексты видны,
крестик, Restore, Privacy и Terms нажимаются, под картинкой нет пустых полос.
[Подробнее](./layout.md#ipad-и-iphone-se).
