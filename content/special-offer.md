# Спешл оффер (от Adapty)

Это второй экран покупки из Adapty. Он открывается после того, как пользователь
закрыл обычный paywall без подтверждённой покупки или restore. В Adapty для
него используется отдельный placement `special_offer`.

Эта страница не описывает RU Billing. Российский продукт, СБП/карта и точное
сопоставление с Adapty описаны на странице
[«RU Billing: спешл оффер»](./ru-special-offer.md).

## Когда он показывается

```text
обычный paywall
  ├─ purchase / restore подтвердили Premium → главный экран приложения
  └─ пользователь нажал крестик
       → прочитать special_offer из текущего Adapty Remote Config
       ├─ любое значение, кроме точного boolean true → главный экран приложения
       └─ true → проверить цикл показа (окно оффера / cooldown)
                  ├─ идёт cooldown → главный экран приложения
                  └─ окно оффера активно или пора открыть новое →
                        запросить placement special_offer
                        → показать второй экран со всеми продуктами Adapty
```

Решение сводится к флагу текущего Remote Config плюс циклу показа:

```text
special_offer == true и окно оффера активно → показать Special Offer
special_offer == true, но идёт cooldown      → не показывать
любое другое значение                        → не показывать
```

Флаг — основной gate; поверх него приложение чередует окно показа и cooldown
(см. ниже). Других условий приложение не добавляет. Если Adapty вернул
configured fallback, приложение читает флаг из фактически загруженного payload
и не добавляет отдельный fallback-gate.

## Cooldown и окно показа

Пока `special_offer = true`, второй экран показывается не безусловно, а циклом
«окно оффера → cooldown»:

- при первом подходящем закрытии обычного paywall открывается **окно оффера**
  (в текущей реализации — 24 часа); внутри него оффер появляется при каждом
  подходящем закрытии;
- когда окно истекает, начинается **cooldown** такой же длительности (24 часа),
  в течение которого оффер не показывается, даже если флаг всё ещё `true`;
- после cooldown цикл повторяется новым окном.

Цикл продвигается по событиям закрытия paywall; окно и cooldown хранятся как даты
в приложении. Обратный отсчёт на экране идёт до конца окна оффера — на нуле экран
закрывается и стартует cooldown. Выключение флага в Adapty, подтверждённая
покупка и перевод часов назад сбрасывают цикл к началу.

## Какие продукты показываются

Платформа передаёт **все** варианты фактически полученного ответа Adapty и
сохраняет их порядок. Она не объединяет их и не оставляет только две карточки.

Ограничение количества карточек возможно только как явное решение конкретного
приложения.

## Если Adapty вернул запасной экран

Платформа использует экран, варианты покупки и Remote Config из того ответа,
который был реально получен. Она не смешивает запрошенный и запасной ответы и
не загружает их заново перед показом.

![Шаг 1 — обычный экран подписки](../public/guides/readme/References/special-offer-step-1-paywall.png)

![Шаг 2 — спешл оффер Adapty после закрытия первого экрана](../public/guides/readme/References/special-offer-step-2-offer.png)

Кадры показывают только порядок экранов. Фон, тексты, число карточек, скидка и
legal-ссылки принадлежат приложению и ответу Adapty.

## Как проверить

1. Обычный paywall всегда появляется первым.
2. Подтверждённый Premium сразу ведёт на главный экран приложения.
3. Без точного `special_offer = true` второй экран не появляется.
4. При `special_offer = true` и активном окне оффера второй экран показывается.
5. На втором экране видны все продукты в порядке Adapty.
6. Повторное подходящее закрытие внутри окна снова открывает экран.
7. После истечения окна начинается cooldown: оффер не показывается до конца cooldown, затем цикл повторяется.
8. Выключение флага, подтверждённая покупка и перевод часов назад сбрасывают цикл.
9. Безопасная демонстрация не совершает настоящих финансовых операций.
