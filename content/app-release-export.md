# Как подготовить приложение к отправке в Codemagic

> **Главное правило:** приложение продолжаем разрабатывать в основной ветке `main`, где пакеты платформы подключены как обычно. Ветка `release/<версия>` нужна **только для сборки и отправки этой версии** через Codemagic. Новые правки в неё не вносим.

Перед началом сохраните изменения приложения в коммит и выставьте нужную версию в Xcode. Работайте в обычной ветке приложения: вручную создавать релизную ветку не требуется.

## Подготовить релиз

В терминале из корня репозитория приложения выполните:

```bash
bash Scripts/prepare_release.sh
```

Дождитесь сообщения `Ветка release/<версия> отправлена в GitHub`. Например,
для версии `1.4.0` появится `release/1.4.0`. В Codemagic нажмите **Start new build**,
выберите эту ветку и workflow для App Store. Готовый IPA проверяется до отправки
в App Store Connect; при ошибке проверки публикация не начинается.

Если скрипта нет, его один раз подключает владелец приложения —
[инструкция установки](#установка-для-владельца-приложения).

## Поручить агенту

Откройте Codex или Claude в репозитории приложения и отправьте:

```text
Подготовь релиз этого приложения: проверь сохранённые изменения и версию в Xcode, запусти bash Scripts/prepare_release.sh без флагов. Если скрипта нет или он устарел, сообщи владельцу, что нужно установить или обновить ReleaseTools. При любой ошибке остановись и покажи её. Убедись, что release/<версия> отправлена в GitHub; при наличии доступа запусти в Codemagic релизный workflow из этой ветки и дождись проверки IPA. Сообщи ветку, результат и ссылку на сборку; дальнейшую разработку веди в main.
```

## Зачем нужен скрипт и что он делает

Во время разработки приложение может скачивать пакеты нашей платформы из Git. Перед релизом скрипт готовит **отдельную версию проекта для сборки**:

1. Проверяет, что изменения сохранены в коммит, а версия приложения указана в Xcode.
2. Копирует код пакетов нашей платформы внутрь проекта и переключает Xcode на эти локальные копии. Сторонние зависимости не меняет.
3. Проверяет, что в подготовленном проекте нет ссылок на Git нашей платформы, и пробует собрать его без подписи. Короткий отчёт сохраняет вне релизной ветки и IPA.
4. Создаёт ветку `release/<версия>` с подготовленным проектом и загружает её в GitHub. Обычная ветка разработки остаётся прежней.

После этого разработчик выбирает релизную ветку в Codemagic.

## Что делать после отправки

Ветка `release/<версия>` нужна только для сборки и отправки **этой версии**. Не продолжайте в ней разработку и не переносите её обратно в `main`.

Если позже понадобятся исправления или новые функции, работайте в `main` с пакетами платформы. Для следующей версии снова запустите подготовку: появится новая релизная ветка.

## Установка для владельца приложения

Проверьте, есть ли в репозитории приложения файл `Scripts/prepare_release.sh`. Его **один раз добавляет владелец приложения** из актуального [инструмента платформы](https://github.com/BroadApps-official/broad-platform-integration/blob/main/ReleaseTools/install.sh). Каждому разработчику отдельно устанавливать его не нужно.

Если файла нет, владелец приложения открывает актуальный `broad-platform-integration` и из его корня запускает подходящую команду. Замените `/path/to/App` на путь к приложению, пути `ios/App…` — на пути относительно его корня, `AppScheme` — на имя схемы.

| Как устроено приложение | Какую команду запустить |
|---|---|
| Только проект | `bash ReleaseTools/install.sh /path/to/App ios/App.xcodeproj AppScheme` |
| CocoaPods (например, Usedesk) | `bash ReleaseTools/install.sh /path/to/App ios/App.xcodeproj AppScheme --workspace ios/App.xcworkspace` |
| Свой workspace без CocoaPods | `bash ReleaseTools/install.sh /path/to/App ios/App.xcworkspace AppScheme` |

Для CocoaPods workspace может ещё не существовать. Если в своём workspace несколько проектов приложения, добавьте `--project ios/App.xcodeproj`. Если `Podfile` лежит не рядом с проектом или workspace, добавьте `--podfile path/to/Podfile`. Пути с пробелами заключите в кавычки.

Схема должна быть **Shared**: в Xcode откройте **Product → Scheme → Manage Schemes**, включите **Shared** и сохраните `.xcscheme` в Git.

Установщик добавит шаблон `Scripts/codemagic.release.yaml`, если файла ещё нет. Укажите в нём пути `XCODE_PROJECT`, `XCODE_WORKSPACE` (оставьте пустым для сборки проекта), при необходимости `XCODE_PODFILE`, схему, подпись и публикацию. Проверьте настройку и сохраните файлы в коммит приложения. Уже установленный инструмент обновите вручную: установщик его не перезаписывает.

Версия Swift-пакетов платформы в приложении может быть старой. **Обновлять пакеты только ради появления скрипта не нужно:** инструмент берёт версии, закреплённые в приложении. Если конкретную старую версию он не сможет подготовить, команда остановится с ошибкой — тогда обратитесь к владельцу платформы.

## Если что-то пошло не так

- Команда не появилась в репозитории? Используйте [установку для владельца](#установка-для-владельца-приложения): инструмент подключается один раз.
- Ошибка про `IPHONEOS_DEPLOYMENT_TARGET` и `Pods.xcodeproj`? Используйте блок `post_install` ниже.
- Команда завершилась ошибкой? Не запускайте Codemagic. Прочитайте последнюю строку ошибки и передайте её владельцу приложения или платформы.
- Ветка создана, но не загрузилась в GitHub? Нужен доступ на запись. После получения доступа выполните подсказанную команду `git push origin release/<версия>`.

### CocoaPods и Xcode 27

Если на Xcode 27 и новее сборка падает из-за слишком низкой версии iOS у подов
(`The iOS deployment target ... is set to 12.0, but the range of supported deployment target versions is 15.0 to ...`),
добавьте в `Podfile` блок ниже. Если `post_install` уже есть, добавьте код в него.
Вместо `16.0` укажите минимальную версию iOS приложения.

```ruby
post_install do |installer|
  installer.pods_project.targets.each do |target|
    target.build_configurations.each do |config|
      # Use the app's minimum iOS version.
      config.build_settings['IPHONEOS_DEPLOYMENT_TARGET'] = '16.0'
    end
  end
end
```

Выполните `pod install` и сохраните изменённые `Podfile` и `Podfile.lock` в коммит
приложения, чтобы скрипт и Codemagic использовали эту настройку.
