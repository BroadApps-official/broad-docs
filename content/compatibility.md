# Проверенные версии библиотек

## Самое главное

**Вам не нужно самостоятельно подбирать номера версий.** Опишите агенту, что
должно появиться в приложении. Codex или Claude выберет нужные библиотеки,
возьмёт номера из этой страницы, подключит их и проверит сборку.

Эта страница нужна как список уже проверенных сочетаний. Если здесь написано
`1.0.0`, это означает: команда действительно собирала эту версию вместе с
остальными версиями из таблицы. Агенту не нужно угадывать или брать самый новый
тег только потому, что он появился в GitHub.

## Что написать агенту

Скопируйте задачу ниже и замените текст в угловых скобках:

```text
Подключи BroadApps iOS к этому приложению.

Что должно уметь приложение:
<например: показать готовый экран подписки и поддержать восстановление покупки>

Сделай всё самостоятельно:
1. Определи, какие верхние библиотеки BroadApps нужны для этой задачи.
2. Не подключай вручную библиотеки, которые приходят как зависимости.
3. Возьми проверенные номера версий из Compatibility/current.yml репозитория
   BroadApps-official/broad-platform-integration.
4. Для первого подключения зафиксируй точные проверенные версии.
5. Выполни package resolve и собери основной iPhone target.
6. В конце напиши: что подключено явно, что пришло автоматически, какие версии
   реально записаны в Package.resolved и успешно ли собрано приложение.

Если нужной версии нет в каталоге или Xcode выбрал другой номер — не угадывай.
Остановись и сообщи, какой именно версии или решения команды не хватает.
```

## Какие версии агент должен взять сейчас

| Что проверяется | Текущий проверенный вариант |
|---|---:|
| Минимальная версия iOS | 17.0 |
| Режим языка Swift | 5 |
| `BroadCore` | [`1.0.0`](https://github.com/BroadApps-official/broad-core-ios/releases/tag/1.0.0) |
| `BroadExtensions` | [`1.0.0`](https://github.com/BroadApps-official/broad-extensions-ios/releases/tag/1.0.0) |
| `BroadMonetization` | [`1.0.0`](https://github.com/BroadApps-official/broad-monetization-ios/releases/tag/1.0.0) |
| `BroadUIFlows` | [`1.0.0`](https://github.com/BroadApps-official/broad-ui-flows-ios/releases/tag/1.0.0) |
| Последняя общая проверка | 25 августа 2026 года |

**Не надо подключать все четыре библиотеки.** Таблица показывает версии всех
частей платформы, но приложение берёт только те верхние библиотеки, которые
решают его задачи.

## Пример: нужен готовый экран подписки

Агент подключает только `BroadUIFlows` версии `1.0.0` к основному target
приложения. Swift Package Manager сам загрузит нужные ему
`BroadMonetization`, `BroadCore`, Adapty и Swinject.

Агент не должен второй раз добавлять `BroadMonetization` и `BroadCore` «на
всякий случай». Явно они нужны только тогда, когда код самого приложения
напрямую импортирует их публичный API.

Если приложению дополнительно нужны независимые HEX-цвета, работа с клавиатурой
или навигационные утилиты, агент добавит ещё `BroadExtensions` версии `1.0.0`.

## Что означает «версии совместимы»

У каждой библиотеки свой репозиторий и свой номер версии. Поэтому теоретически
можно случайно собрать приложение из старой версии одной библиотеки и новой
версии другой.

Каталог совместимости убирает эту неопределённость. Он хранит точный снимок:

1. какие версии библиотек были взяты;
2. собирается ли каждая библиотека отдельно;
3. собираются ли они вместе в демонстрационном iPhone-приложении;
4. когда эта общая проверка выполнялась последний раз.

Статус `passed` означает только, что общий код и пример приложения собрались.
Он **не подтверждает** настоящую оплату, production backend, ключи, URL и
настройки конкретного приложения. Такие вещи агент проверяет уже внутри самого
приложения вместе с данными, которые передала команда.

## Почему агент сначала ставит точную версию

При первом подключении важна повторяемость: если в каталоге проверена `1.0.0`,
агент ставит именно `1.0.0`. Тогда при ошибке понятно, что использован тот же
код, который уже проходил общую проверку.

Позже команда может разрешить диапазон `from: "1.0.0"`. В таком режиме Xcode
имеет право скачать более новую версию до `2.0.0`. Это удобно для обновлений,
но фактически выбранный номер всё равно надо посмотреть в `Package.resolved`.

Простое правило:

| Ситуация | Что делает агент |
|---|---|
| Первое подключение или миграция | Ставит точные номера из каталога |
| Команда явно разрешила автоматические совместимые обновления | Использует `from`, затем проверяет фактический номер |
| Xcode выбрал номер, которого нет в каталоге | Не продолжает молча, а сообщает команде |

## Что агент должен проверить перед завершением

- package resolve завершился без старых local path dependencies;
- основной iPhone target собирается;
- явно подключены только нужные верхние библиотеки;
- автоматически пришедшие зависимости не продублированы;
- в `Package.resolved` видны фактически выбранные версии;
- эти версии совпадают с текущим проверенным набором;
- ключи, URL, реальные покупки и backend не объявлены проверенными без
  отдельной проверки конкретного приложения.

## Где лежит источник для агента

Актуальная машиночитаемая запись находится в
[`Compatibility/current.yml`](https://github.com/BroadApps-official/broad-platform-integration/blob/main/Compatibility/current.yml).
Агент должен читать этот файл перед подключением или обновлением библиотек.
