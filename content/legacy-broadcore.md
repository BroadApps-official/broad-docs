# Старый BroadCore: куда переехал

**BroadCore как Swift-модуль продолжает существовать.** Изменился способ его распространения: старый репозиторий `BroadApps-official/BroadCore` не является актуальным источником для нового подключения. Теперь отдельные части платформы выпускаются в публичных репозиториях.

Если приложение уже работает на старой версии, сначала разберите его зависимости. Простая замена URL не гарантирует совместимость всех использованных классов и поведения.

## Отличайте имя модуля от адреса репозитория

| Что вы встретили | Что это означает | Как поступить |
|---|---|---|
| `import BroadCore` | Имя библиотеки в Swift | Не меняйте его только из-за переезда; проверьте, откуда она подключена |
| `BroadApps-official/BroadCore.git` | Старый источник общей платформы | Для существующего приложения составьте план перехода |
| `BroadApps-official/broad-core-ios.git` | Актуальный публичный источник Core | Используйте нужную версию из каталога |
| Папка BroadCore на Mac | Возможно, локальная копия | Проверьте, участвует ли она в сборке и какие модули предоставляет |
| `broad-platform-integration` | Каталог совместимых версий и проверки общего примера | Читайте документацию; в app target его не добавляют |

В Xcode посмотрите **Project → Package Dependencies → URL**. Название `BroadCore` в левой панели и строка `import` сами по себе не показывают, используется старый репозиторий или новый.

## Где теперь искать нужную функцию

| Функция старой общей платформы | Актуальная часть | Что читать |
|---|---|---|
| Запуск, состояния, кеш, ошибки, повтор, логи | [broad-core-ios](https://github.com/BroadApps-official/broad-core-ios) | [BroadCore](./broad-core.md) |
| Цвета, шрифты, клавиатура, жест возврата | [broad-extensions-ios](https://github.com/BroadApps-official/broad-extensions-ios) | [BroadExtensions](./broad-extensions.md) |
| Покупка, восстановление, подтверждение доступа, RU Billing | [broad-monetization-ios](https://github.com/BroadApps-official/broad-monetization-ios) | [BroadMonetization](./broad-monetization.md) |
| Готовые первые экраны и платёжные сценарии | [broad-ui-flows-ios](https://github.com/BroadApps-official/broad-ui-flows-ios) | [BroadUIFlows](./broad-ui-flows.md) |
| Проверенные сочетания версий | [Compatibility/current.yml](https://github.com/BroadApps-official/broad-platform-integration/blob/main/Compatibility/current.yml) | [Совместимость](./compatibility.md) |
| Тексты, брендинг, backend конкретного приложения | Репозиторий самого приложения | [Создание приложения](./app-creation.md) |

Это карта областей ответственности, а не таблица автоматического переименования каждого класса. Для использованного API сравните фактическую декларацию в старом коде с публичным API нового модуля.

## Если создаёте новое приложение

Выберите функции по [таблице модулей](./module-selection.md), подключите публичные HTTPS-адреса и точные версии. Старый BroadCore для этого маршрута не нужен.

Не ищите запускаемый Xcode-проект в корне каждого репозитория платформы: модули представлены Swift Package с `Package.swift`. Готовый учебный app-проект находится в [BroadStart](https://github.com/BroadApps-official/broad-docs/tree/main/examples/first-app), расширенный технический пример — в [BroadAppTemplate](https://github.com/BroadApps-official/broad-platform-integration/tree/main/Examples/BroadAppTemplate).

## Если приложение уже выпущено

Сохраните рабочую точку, перечислите реально используемые функции, затем выберите минимальную группу зависимостей, которую надо переключить вместе. В неё входят старые и новые модули с совпадающими именами. После переключения проверьте каждый затронутый сценарий.

Скопированные в приложение файлы могут содержать изменения разработчика. Сначала сравните их с общей версией: нужное поведение нельзя потерять вместе с удалением дубликата. Обёртки и бизнес-правила приложения остаются в его репозитории.

[Полная пошаговая миграция](./legacy-app-migration.md) объясняет поиск подключений, замену групп, проверку и возврат к рабочему состоянию.

## Как пользоваться старыми материалами

Старый исходник полезен, чтобы восстановить прежнее поведение, параметры вызовов и историю решений. Он не определяет актуальные адреса, версии и правила для нового приложения.

Если Codex или Claude нашли старый BroadCore, укажите агенту текущий [каталог платформы](https://github.com/BroadApps-official/broad-platform-integration) и репозиторий вашего приложения. Пусть он сначала сопоставит используемые функции, а не заменяет все `import` и классы по совпадению названий.
