# Какие части платформы выбрать

Сначала перечислите функции приложения, затем отметьте библиотеки, чей код оно будет использовать. **Не обязательно подключать все четыре модуля. Несколько модулей допустимы**, если каждый нужен для конкретной функции.

Есть два разных вопроса: какие пакеты Xcode должен скачать и какие продукты подключить к вашему target. Их различие особенно важно для готовых экранов, которые используют Core и Monetization внутри себя.

## Четыре модуля и их задачи

| Модуль | Когда нужен | Чего от него не ожидать |
|---|---|---|
| **BroadExtensions** | Цвет из HEX, шрифты, закрытие клавиатуры, жест возврата | Не запускает приложение и не подключает оплату |
| **BroadCore** | Состояния загрузки и ошибки, последовательность запуска, кеш, ограниченные повторы, логи, механизм ATT | Не рисует paywall и не даёт готовый backend приложения |
| **BroadMonetization** | Покупка, восстановление, подтверждение доступа, Adapty, токены, RU Billing и его опциональные A/B-тесты | Не создаёт дизайн вашего экрана и не знает реквизиты вашего сервера |
| **BroadUIFlows** | Готовый onboarding, paywall, переходы между ними, общие экраны состояний; управление onboarding с собственным дизайном | Не определяет число слайдов, бренд, юридические ссылки и условия вашего продукта |

Код модулей: [Extensions](https://github.com/BroadApps-official/broad-extensions-ios), [Core](https://github.com/BroadApps-official/broad-core-ios), [Monetization](https://github.com/BroadApps-official/broad-monetization-ios), [UIFlows](https://github.com/BroadApps-official/broad-ui-flows-ios). Общие инструкции: [части платформы](./architecture.md).

## Какие зависимости придут вместе

| Добавленный пакет | Что Xcode также скачает по его зависимостям |
|---|---|
| `broad-extensions-ios` | Дополнительные внешние пакеты не нужны |
| `broad-core-ios` | Swinject |
| `broad-monetization-ios` | BroadCore, Adapty и Swinject |
| `broad-ui-flows-ios` | BroadMonetization, BroadCore, Adapty и Swinject |

**BroadExtensions независим.** Он не появляется автоматически при добавлении UIFlows. Если используете `Color(broadHex:)`, подключите Extensions отдельно.

Даже когда из UIFlows вам нужен только onboarding, текущий пакет объявляет зависимости на Monetization и Adapty. «Функция оплаты не используется» не означает «SDK оплаты не скачивается». Если эти зависимости недопустимы в вашем приложении, выберите собственный SwiftUI-onboarding с подходящими механизмами Core и отдельно проверьте правила ATT. Готовый сценарий UIFlows при этом не подключён.

## Что добавить в target при прямом import

Swift Package — скачиваемый пакет. **Product** — библиотека из этого пакета. **Target** — собираемое приложение, которому эта библиотека нужна.

| Ситуация | Что сделать |
|---|---|
| Core нужен только внутри выбранного модуля | Xcode скачает его как зависимость; app-коду его product не нужен |
| В Swift-файле приложения есть `import BroadCore` | Добавьте product BroadCore в app target |
| Экран использует `LoadableState` и `BroadLoadableView` | Нужны прямые products BroadCore и BroadUIFlows |
| Приложение создаёт модели или сервисы Monetization | Добавьте product BroadMonetization, даже если UIFlows уже скачал пакет |
| Два маршрута привели к одному публичному пакету | Используйте один package identity и совместимые версии; не копируйте его исходники |

Проверяйте **General → Frameworks, Libraries, and Embedded Content** у основного приложения. Видеть пакет в левой панели Xcode недостаточно: product мог остаться с **Add to Target = None**.

![BroadStart: Core и Extensions указаны в target, Swinject виден среди скачанных зависимостей](../public/guides/start/xcode-target.png)

Явно указанный product не означает вторую копию пакета. Дубли появляются, например, когда одновременно подключены новый публичный пакет и старый BroadCore с теми же модулями или скопированными исходниками. Это разбирается в [миграции](./legacy-app-migration.md).

## Пять практических наборов

| Приложение | С чего начать | Дополнительные products по прямому API |
|---|---|---|
| Учебный каталог BroadStart | Core + Extensions | Никаких: код использует состояния и HEX-цвет |
| Свой интерфейс подписки | Monetization | Core, если приложение создаёт его состояния, логи или bootstrap; Extensions для утилит |
| Готовый onboarding и paywall | UIFlows | Monetization и Core, если приложение напрямую собирает их конфигурацию или сервисы |
| Только цвет, шрифты, клавиатура | Extensions | Core и монетизация не нужны |
| Уже есть готовая собственная покупка | Сначала аудит существующих сервисов | Не создавайте второй центр управления покупкой только ради подключения платформы |

В реальном приложении набор **UIFlows + Monetization + Core** может быть правильным: готовый экран, конфигурация оплаты и общие состояния используются напрямую. Правило «добавь только самый верхний модуль и никогда остальные» неверно.

## Пример выбора для BroadStart

Требование: показать материалы, дать открыть один, объяснить пустой ответ и ошибку. Подписки и сервер не нужны.

1. Для `LoadableState<[Lesson]>` и `AppError` выбираем **BroadCore**.
2. Для `Color(broadHex:)` выбираем **BroadExtensions**.
3. Для двух простых экранов используем SwiftUI `NavigationStack` — готовый платёжный сценарий не требуется.
4. Добавляем два публичных пакета и два product в target BroadStart.
5. Проверяем, что Package.resolved содержит Core, Extensions и зависимость Core — Swinject.

![Список BroadStart использует состояния Core](../public/guides/start/app-list.png)
![Пустой результат обрабатывается самим интерфейсом приложения](../public/guides/start/app-empty.png)

Если удалить использование HEX-утилиты и заменить цвет стандартным `Color.blue`, Extensions этому примеру больше не понадобится. Наличие библиотеки должно объясняться её использованием, а не привычкой.

## Что всегда настраивает приложение

| Область | Данные и решения приложения |
|---|---|
| Внешний вид | Тексты, цвета, изображения, макеты, порядок экранов |
| Сервер | Адреса запросов, формат ответа, способ доступа, перевод данных в модели |
| Adapty | Публичный SDK-ключ именно этого приложения, placement ID, нужные сценарии |
| RU Billing | Backend-каталог, точные ID, контракты checkout и подтверждения, решение включить A/B |
| Поддержка | Адрес письма, сведения приложения, Usedesk при необходимости |
| Разрешения | Продуктовая необходимость и корректный момент системного запроса |

Наличие пакета не активирует RU Billing или его A/B-тест автоматически. Существующий обычный paywall не нужно менять ради подключения необязательного эксперимента: [порядок расширения RU Billing](./ru-billing-ab-platform.md).

## Как выбрать версии

Возьмите набор из [каталога совместимости](./compatibility.md), затем посмотрите версию каждого выбранного модуля. Проверенный здесь набор **4.1.1** содержит Core **2.1.0**, Extensions **1.0.1**, Monetization **4.0.0**, UIFlows **4.0.0**.

**Exact Version** фиксирует одну версию. **Up to Next Major Version** разрешает совместимый диапазон по номеру версии; при обновлении Xcode может выбрать более свежий выпуск в нём. Для первого воспроизводимого подключения и миграции используйте exact-версии набора и сохраняйте Package.resolved.

Репозиторий [broad-platform-integration](https://github.com/BroadApps-official/broad-platform-integration) хранит каталог и проверки сочетаний. Он не является пятой библиотекой, которую нужно добавить в app target. Старый [BroadCore](./legacy-broadcore.md) тоже не является актуальным общим пакетом для всего приложения.

## Если подключаете через Package.swift

Этот фрагмент предназначен для собственного Swift Package. В обычном `.xcodeproj` те же настройки выполняются через Xcode; создавать дополнительный Package.swift только ради двух библиотек не нужно.

```swift
dependencies: [
    .package(
        url: "https://github.com/BroadApps-official/broad-core-ios.git",
        exact: "2.1.0"
    ),
    .package(
        url: "https://github.com/BroadApps-official/broad-extensions-ios.git",
        exact: "1.0.1"
    )
],
targets: [
    .target(
        name: "AppFeature",
        dependencies: [
            .product(name: "BroadCore", package: "broad-core-ios"),
            .product(name: "BroadExtensions", package: "broad-extensions-ios")
        ]
    )
]
```

Здесь одновременно заданы источники пакетов и products, которые использует target `AppFeature`. Имя target и путь к его исходникам должны соответствовать вашему пакету. [Полный Xcode-пример с зафиксированными настройками](https://github.com/BroadApps-official/broad-docs/blob/main/examples/first-app/project.yml).

## Проверьте свой выбор

Напротив каждого прямого `import Broad…` укажите product в target; напротив каждого product — функцию, которой он нужен. Проверьте отсутствие старого URL и локальных копий, согласованность версий и запуск нужного сценария. Затем продолжайте [подключение](./getting-started.md) или [создание приложения](./app-creation.md).
