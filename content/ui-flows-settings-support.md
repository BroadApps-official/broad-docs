# Экран настроек и экран поддержки

В настройках человек управляет приложением и находит помощь. **«Онлайн-чат» открывает переписку внутри приложения. «Написать в поддержку» готовит письмо.** По названию строки должно быть понятно, куда приведёт нажатие.

Шесть приложений и отдельная демонстрация письма — в одном ряду. У всех видео одинаковые пропорции, пауза, перемотка, полный экран и кнопка «Подписи».

Первые шесть роликов записаны из работающих приложений в iPhone Simulator 8 сентября 2026 года. Последний — **учебный экран на SwiftUI с вымышленными данными, не системный Apple Mail**. Он показывает содержание письма, закрытие, повторное открытие и вариант без настроенной почты. Отправка в демонстрации отключена. Паузы оператора сокращены; переходы сохранены с исходной скоростью. Идентификаторы в записях скрыты.

| 5007 / CheaterBuster | Компактные группы, Support, сообщение о недоступной почте | Одной просьбы настроить Mail недостаточно: человеку нужен способ связаться сейчас |

Примеры помогают выбрать оформление и навигацию. Состав настроек определяет продукт: переносить все строки из другого приложения не нужно.

## Как собрать понятный экран настроек

Начните со списка действий. Для каждой строки задайте название, результат нажатия и состояние, когда действие недоступно. Объедините близкие действия в небольшие группы.

| Группа | Возможные строки | Что должно происходить |
|---|---|---|
| Подписка | Получить Premium, восстановить покупки, управление подпиской | Открывается соответствующий сценарий оплаты или управления. После возврата статус обновляется |
| Приложение | Язык, оформление, уведомления, кэш | Видно текущее значение; выбор применяется и сохраняется. Системный отказ в уведомлениях отражается в интерфейсе |
| Поддержка | Онлайн-чат, написать в поддержку | Каждый канал открывается отдельно и позволяет вернуться в настройки |
| О приложении | Оценить, поделиться, документы, версия | Открываются ссылки и системные окна именно этого приложения |
| Данные | Очистить историю, ID аккаунта | Перед удалением есть подтверждение и отмена. ID можно скопировать без ручного переписывания |

У пользователя без подписки показывайте предложение Premium, у подписанного — статус и управление. Restore показывает процесс и результат, включая случай «покупки не найдены». Не оставляйте бесконечную загрузку и не показывайте успех до ответа платёжного сервиса.

Для подписки App Store открывайте системное управление подписками. Закрытие этого окна ничего само по себе не отменяет. У RU Billing свой маршрут — [управление RU-подпиской](./ru-billing.md). Ссылки на условия, политику и поддержку берите из конфигурации текущего приложения.

## Информация о компании

Добавьте пункт **«Информация о компании»**, как в 5115. Он открывает экран с
названием компании, регистрационным номером, BRN, юридическим адресом и
пояснением о поставщике услуги. Крестик закрывает экран и возвращает в настройки.

**Данные одинаковые для всех проектов. Актуальные реквизиты берите из
[общего документа Kaiten — «Доп. условия при использовании 1payments»](https://broadapps.kaiten.ru/documents/d/fe97e05e-1386-49ab-a175-1182384483df#Доп-условия-при-использование-1payments-b3fda0b7).**
Документ доступен после входа в рабочий Kaiten. Переводите подписи полей,
сохраняя написание названия компании, номеров и адреса из источника.

[Скриншот экрана 5115 и ссылки на его код](./ru-billing.md#данные-о-компании).

## Онлайн-чат: от строки до переписки

Ожидаемый маршрут: **Настройки → Онлайн-чат → загрузка → переписка → Назад → Настройки**. Пользователь сразу понимает, что чат открывается внутри приложения.

1. Получите конфигурацию поддержки для текущего приложения. Для Usedesk используйте [отдельную инструкцию](./usedesk.md): готовый SDK, Company ID, Channel ID и подтверждённое назначение Token. Наличие BroadUIFlows само по себе не подключает чат.
2. Перед открытием передайте стабильный ID аккаунта, по которому поддержка найдёт пользователя. Он должен соответствовать ID в настройках. Случайный новый ID при каждом входе разрывает историю обращений.
3. На время открытия покажите загрузку и защититесь от повторного нажатия. Несколько быстрых тапов не должны создавать несколько экранов чата.
4. При ошибке соединения покажите понятное сообщение, повтор и альтернативу «Написать на почту». При отсутствии конфигурации не оставляйте строку, ведущую в пустой экран.
5. Проверьте клавиатуру, ввод, вложения и возврат. Поле ввода остаётся над клавиатурой; повторное открытие работает после закрытия.

В видео 232 и 5115 показаны настоящий интерфейс Usedesk, открытие клавиатуры и возврат. **Сообщения поддержке при записи не отправлялись**; эти ролики не подтверждают доставку сообщений или ответ оператора. Доставку проверяют отдельно в согласованном тестовом канале.

## Письмо: что подготовить до открытия Mail

Нажатие «Написать в поддержку» готовит черновик: получатель и тема уже заполнены, под ними есть место для проблемы и полезная диагностика. Пользователь читает письмо, дополняет его и сам решает, отправлять ли его.

| Часть письма | Что подставить | Для чего |
|---|---|---|
| Кому | Support email из конфигурации приложения | Обращение попадёт в нужную поддержку |
| Тема | Название приложения и Support; при необходимости название сценария | Письмо можно быстро найти и распределить |
| Описание | «Что случилось», «Как повторить», «Что ожидали» | Пользователю легче описать проблему, чем писать с пустого листа |
| Сборка | Название, установленная версия, build, bundle ID | Поддержка понимает, какой код работает у пользователя |
| Среда | Время формирования, iOS, модель устройства, язык и часовой пояс | Помогает воспроизвести проблему |
| Аккаунт | Стабильный ID из настроек; при необходимости явно подписанный backend ID | Позволяет найти правильную учётную запись |
| Подписка | Текущий статус; идентификаторы профиля и продукта только если нужны для разбора оплаты | Помогает связать обращение с платёжной интеграцией |
| Вложение | Небольшой очищенный диагностический файл | Даёт контекст последних действий без лишней переписки |

Платёжные идентификаторы — диагностические поля конкретной интеграции, а не обязательная часть каждого письма. Не добавляйте сырой receipt, полный ответ SDK, токены, пароли, содержимое переписок или данные банковской карты. Неизвестное значение обозначайте как «недоступно»; не блокируйте поддержку ожиданием сети без ограничения времени.

В 5007 используется файл `support-log.txt`, в 232 — `app_log.txt`, в 5142 — `diagnostics.txt`. Имя может отличаться. Важно, чтобы содержимое было очищено **до** прикрепления. Через обычный `mailto:` вложение не передаётся; нельзя писать «лог приложен», если файла фактически нет.

## Как открыть письмо и обработать закрытие

Проверяйте `MFMailComposeViewController.canSendMail()` перед созданием системного окна. Если почта доступна, передайте получателей, тему, текст и доступное вложение; затем представьте контроллер. Apple описывает этот порядок в [документации MessageUI](https://developer.apple.com/documentation/messageui/mfmailcomposeviewcontroller).

Обработчик завершения должен закрыть контроллер и очистить состояние показа. В SwiftUI это обычно означает сброс значения, управляющего `.sheet`, после callback представленного контроллера. Проверьте цикл **открыть → закрыть → открыть снова**: второй вход не должен показывать пустое окно или старую загрузку.

| Результат Mail | Реакция приложения |
|---|---|
| Cancelled | Вернуться в настройки; не показывать «отправлено» |
| Saved | Вернуться; при необходимости подтвердить сохранение черновика |
| Sent | Можно подтвердить передачу письма в очередь отправки. Это не доказательство получения оператором |
| Failed | Показать ошибку и дать повторить или скопировать адрес |

Результаты определяет [MFMailComposeResult](https://developer.apple.com/documentation/messageui/mfmailcomposeresult). Открытие окна и отправка письма — разные события; не считайте нажатие на строку успешным обращением.

## Если Mail недоступен

Такое состояние возможно и на устройстве без настроенной почты. После нажатия человек должен получить результат, а не остаться на том же экране без объяснения.

1. Если предусмотрен переход в другое почтовое приложение, сформируйте `mailto:` с кодированием темы и текста через `URLComponents`.
2. Проверьте результат открытия URL. Сам факт, что URL удалось создать, не означает, что приложение смогло его открыть.
3. Если открыть письмо не получилось, покажите **полный адрес поддержки**, кнопку **«Скопировать адрес»** и **«Закрыть»**. Если подключён чат, предложите его как альтернативу.
4. После копирования покажите короткое подтверждение. Пользователь должен понимать, что именно скопировано и куда можно написать.

Учебное видео показывает такой запасной вариант. Записи приложений рядом помогают увидеть, чего не хватает в сообщении только с кнопкой OK или в полностью молчаливом отказе.

## Как записать пример без физического iPhone

**Настройки, чат, ошибки и возврат записываются в Simulator из приложения.** Для демонстрации содержания письма используйте отдельный экран предпросмотра с фиктивными данными и выключенной отправкой. На самом экране и в подписи ролика укажите, что это демонстрация, а не Apple Mail.

В последнем ролике именно такой вариант: SwiftUI-экран показывает поля и пример вложения, прокручивается, закрывается и повторно открывается. Рядом записан путь «Почта недоступна → Скопировать адрес». Исходник учебного экрана находится в репозитории документации: `examples/settings-support/MailDemo.swift`.

Предпросмотр позволяет объяснить содержание и навигацию без физического устройства. Он не проверяет системный Mail, реальное прикрепление файла, сохранение черновика и отправку. Эти возможности MessageUI проверяются отдельно в среде, где `canSendMail()` возвращает `true`; подменять результат этой проверки в рабочем приложении не нужно.

## Что настроить разработчику

| Входные данные | Где используются |
|---|---|
| Названия и группы строк | Экран настроек текущего продукта |
| Адрес поддержки и шаблон темы | Письмо и сообщение при недоступной почте |
| Конфигурация чата | Сервис поддержки текущего приложения; реальные значения не попадают в публичные примеры |
| Единый ID аккаунта | Настройки, чат и диагностика письма |
| Версия/build и состояние подписки | Подготовка диагностических полей |
| Генератор очищенного лога | Вложение, если оно доступно и нужно |
| Обработчики открытия, ошибки и закрытия | Навигация, повторное открытие и защита от двойных нажатий |

Экран настроек и подключение поддержки остаются частью приложения. Эта статья показывает примеры; она не добавляет обязательный общий Settings-flow или автоматическую интеграцию Usedesk в платформу.

## Как принять готовую реализацию

1. Откройте настройки без подписки и с активной подпиской. Статус, Premium и управление соответствуют пользователю; текст не скачет после загрузки.
2. Нажмите чат несколько раз подряд. Открывается один экран. Проверьте загрузку, отсутствие сети, клавиатуру, закрытие и повторный вход.
3. Проверьте подготовленное письмо: правильный адрес приложения, установленный build, ID из настроек и понятное место для описания. Прочитайте вложение и убедитесь, что лишних данных нет.
4. Пройдите закрытие и повторное открытие письма. Отмена не считается отправкой, ошибка не выглядит как успех.
5. Проверьте недоступную почту: виден полный адрес, копирование работает, закрытие возвращает в настройки. Неудачный `mailto:` тоже обработан.
6. Проверьте длинные переводы, увеличенный шрифт и небольшой экран. Все строки доступны, нижние кнопки не скрыты; после возврата сохраняется понятное положение списка.
