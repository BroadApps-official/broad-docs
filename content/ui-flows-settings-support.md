# Экран настроек и экран поддержки

В настройках человек управляет приложением и находит помощь. **«Онлайн-чат» открывает переписку внутри приложения. «Написать в поддержку» готовит письмо.** По названию строки должно быть понятно, куда приведёт нажатие.

## Как подключить хост

В BroadUIFlows 7.0.0 передайте `BroadSettingsHost` настоящий вызов пейвола
приложения. Ниже фрагмент экрана: `settings` — его конфигурация, `restore` —
действие восстановления, `router` — существующий маршрутизатор приложения,
`MySettings` — ваша вёрстка из готового `screen`.

```swift
BroadSettingsHost(
    configuration: settings,
    showPaywall: { router.showPaywall(placement: .settings) },
    restorePurchases: restore
) { screen in
    MySettings(screen: screen)
}
```

`showPaywall` обязателен — это единственное ломающее изменение 7.0.0;
остальной код совместим. [Переход со старых версий](./compatibility.md#обновление-с-набора-6-5-0-на-7-0-0).
Хост ведёт действия настроек и показ письма. Обработку недоступной почты
с адресом и копированием обеспечивает приложение по контракту `SupportEmail.md`;
Usedesk подключается отдельно к строке «Онлайн-чат».

Если работаете с агентом, отправьте ему:

```text
Подключи настройки через BroadSettingsHost с настоящим showPaywall маршрутизатора приложения. Проверь, что обе кнопки подписки открывают один пейвол через общий gate, письмо соответствует SupportEmail.md, а без Mail виден адрес с копированием. Покажи результат каждого сценария.
```

## Что проверить

1. `screen.showPaywall()` и `screen.manageSubscription()` по отдельности открывают
   один пейвол приложения через общий gate; App Store не открывается. При двух
   одновременных нажатиях срабатывает одно действие.
2. Письмо соответствует [контракту SupportEmail.md](https://github.com/BroadApps-official/broad-platform-integration/blob/main/Documentation/SupportEmail.md):
   адрес своего приложения, установленный build, все доступные ID текущего аккаунта,
   подтверждённый баланс при наличии токенов и очищенный support log; строки `Bundle` нет.
3. Письмо закрывается и открывается снова. Без Mail виден полный адрес,
   копирование работает; если подключён чат, он открывается отдельной строкой и позволяет вернуться.

## Как собрать понятный экран настроек

> [!TIP]
> **Логику строк не пишите сами.** Оберните экран в `BroadSettingsHost` — он даёт
> restore с результатом, открытие пейвола, документы в приложении, письмо в
> поддержку, копирование ID с подтверждением, оценку, «поделиться», версию и сборку.
> Одно касание за раз: первое нажатие закрывает остальные строки на 400 мс.
> [Пример](./broad-ui-flows.md).

Начните со списка действий. Для каждой строки задайте название, результат нажатия и состояние, когда действие недоступно. Объедините близкие действия в небольшие группы.

| Группа | Возможные строки | Что должно происходить |
|---|---|---|
| Подписка | Получить Premium, статус подписки, восстановить покупки | «Получить Premium», статус и нарисованная «Manage subscription» открывают пейвол. Restore показывает результат. После покупки статус обновляется |
| Приложение | Язык, оформление, уведомления, кэш | Видно текущее значение; выбор применяется и сохраняется. Системный отказ в уведомлениях отражается в интерфейсе |
| Поддержка | Онлайн-чат, написать в поддержку | Каждый канал открывается отдельно и позволяет вернуться в настройки |
| О приложении | Оценить, поделиться, документы, версия | Открываются ссылки и системные окна именно этого приложения |
| Данные | Очистить историю, ID аккаунта | Перед удалением есть подтверждение и отмена. ID можно скопировать без ручного переписывания |

У пользователя без подписки показывайте предложение Premium, у подписанного — статус. Restore показывает процесс и результат, включая случай «покупки не найдены». Не оставляйте бесконечную загрузку и не показывайте успех до ответа платёжного сервиса.

> [!IMPORTANT]
> При покупках через Adapty и App Store не добавляйте «Cancel subscription»,
> системный экран и веб-страницу подписок App Store, даже если они есть в Figma.
> Отмена доступна только для RU-подписки через backend — [подробнее](./ru-billing.md).

Ссылки на условия, политику и поддержку берите из конфигурации текущего приложения.

## Информация о компании — только с RU Billing

Пункт **«Информация о компании»** нужен **только если в приложении подключён RU
Billing** (оплата картой и СБП через 1payments). Без RU Billing этого пункта в
настройках нет, даже если он есть в макете или в похожем приложении.

С RU Billing пункт открывает экран, как в 5115: название компании,
регистрационный номер, BRN, юридический адрес и пояснение о поставщике услуги.
Крестик закрывает экран и возвращает в настройки.

**Реквизиты всегда уточняйте на актуальность.** Источник —
[общий документ Kaiten «Доп. условия при использовании 1payments»](https://broadapps.kaiten.ru/documents/d/fe97e05e-1386-49ab-a175-1182384483df#Доп-условия-при-использование-1payments-b3fda0b7)
(нужен вход в рабочий Kaiten), но перед добавлением и перед выпуском подтвердите
у аккаунт-менеджера, что данные в нём актуальны. Не переносите реквизиты из другого
приложения или со скриншота. Подписи полей переводятся, а название компании,
номера и адрес пишутся как в источнике.

[Скриншот экрана 5115 и ссылки на его код](./ru-billing.md#данные-о-компании).

## Онлайн-чат: от строки до переписки

Ожидаемый маршрут: **Настройки → Онлайн-чат → загрузка → переписка → Назад → Настройки**. Пользователь сразу понимает, что чат открывается внутри приложения.

1. Получите конфигурацию поддержки для текущего приложения. Для Usedesk используйте [отдельную инструкцию](./usedesk.md): готовый SDK, Company ID, Channel ID и подтверждённое назначение Token. Наличие BroadUIFlows само по себе не подключает чат.
2. Перед открытием передайте стабильный ID аккаунта, по которому поддержка найдёт пользователя. Он должен соответствовать ID в настройках. Случайный новый ID при каждом входе разрывает историю обращений.
3. На время открытия покажите загрузку и защититесь от повторного нажатия. Несколько быстрых тапов не должны создавать несколько экранов чата.
4. При ошибке соединения покажите понятное сообщение, повтор и альтернативу «Написать на почту». При отсутствии конфигурации не оставляйте строку, ведущую в пустой экран.
5. Проверьте клавиатуру, ввод, вложения и возврат. Поле ввода остаётся над клавиатурой; повторное открытие работает после закрытия.

В видео 232 и 5115 показаны настоящий интерфейс Usedesk, открытие клавиатуры и возврат. **Сообщения поддержке при записи не отправлялись**; эти ролики не подтверждают доставку сообщений или ответ оператора. Доставку проверяют отдельно в согласованном тестовом канале.

## Письмо: что подготовить до открытия Mail

Нажатие «Написать в поддержку» готовит черновик: получатель и тема уже заполнены, под ними есть место для проблемы и полезная диагностика. Пользователь читает письмо, дополняет его и сам решает, отправлять ли его.

Используйте [машиночитаемый контракт SupportEmail.md платформы](https://github.com/BroadApps-official/broad-platform-integration/blob/main/Documentation/SupportEmail.md)
через `BroadSupportEmailConfiguration` и `BroadSupportLogRecorder`.
Первую строку, заголовки и порядок секций не меняйте; `bundle ID` и строку
`Bundle` в письмо не добавляйте. Пользователь пишет после последнего разделителя.
Для уже определённого RU/ЮKassa-сценария меняется только первая строка по контракту.

Подготовьте входные данные для этой формы:

| Входные данные | Откуда взять | Что проверить |
|---|---|---|
| Адрес и тема | Конфигурация текущего приложения | Обращение идёт в его поддержку |
| Название, версия App Store, установленная версия/build | Конфигурация и метаданные сборки | Опубликованная и установленная версии не перепутаны |
| iOS, модель, локаль и часовой пояс | Текущее устройство | Значения переданы в поля контракта |
| Adapty profileID, backend userID, статус подписки | Текущий аккаунт и последний подтверждённый статус | ID и статус относятся к этому пользователю |
| Все доступные дополнительные ID | Текущий аккаунт, включая ID начисления токенов | Переданы после `Subscription`, без дублирования базовых ID |
| Подтверждённый баланс | Серверный снимок, если приложение использует токены | Неизвестное значение пропущено, настоящий ноль сохранён |
| Support log | `BroadSupportLogRecorder` | Файл очищен и фактически прикреплён |

Не добавляйте сырой receipt/JWS, полный ответ SDK, токены, пароли или платёжные URL.
Отсутствующие значения обрабатывайте по контракту; неизвестный баланс не заменяйте нулём.
Через `mailto:` вложение не передаётся: такой переход не должен обещать приложенный лог.

## Как открыть письмо и обработать закрытие

Вызывайте `screen.contactSupport()` из вёрстки настроек: показ и закрытие письма
ведёт хост. Проверьте цикл **открыть → закрыть → открыть снова**, отмену и ошибку.
Нажатие на строку и передача письма в очередь не доказывают получения оператором.

Ручное подключение composer и условия показа описаны в
[техническом источнике SupportEmail.md](https://github.com/BroadApps-official/broad-platform-integration/blob/main/Documentation/SupportEmail.md#готовая-реализация-в-платформе);
системные результаты — в [документации MessageUI](https://developer.apple.com/documentation/messageui/mfmailcomposeresult).

## Если Mail недоступен

Такое состояние возможно и на устройстве без настроенной почты. После нажатия человек должен получить результат, а не остаться на том же экране без объяснения.

Покажите **полный адрес поддержки**, кнопки **«Скопировать адрес»** и **«Закрыть»**;
после копирования — подтверждение. Если подключён чат, предложите его как альтернативу.
Переход в другое почтовое приложение допустим по условиям `SupportEmail.md`;
неудачное открытие тоже должно возвращать человека к адресу и копированию.

Учебное видео показывает такой запасной вариант. Записи приложений рядом помогают увидеть, чего не хватает в сообщении только с кнопкой OK или в полностью молчаливом отказе.

## Как записать пример без физического iPhone

**Настройки, чат, ошибки и возврат записываются в Simulator из приложения.** Для демонстрации содержания письма используйте отдельный экран предпросмотра с фиктивными данными и выключенной отправкой. На самом экране и в подписи ролика укажите, что это демонстрация, а не Apple Mail.

В последнем ролике именно такой вариант: SwiftUI-экран показывает поля и пример вложения, прокручивается, закрывается и повторно открывается. Рядом записан путь «Почта недоступна → Скопировать адрес». Исходник учебного экрана находится в репозитории документации: `examples/settings-support/MailDemo.swift`.

Предпросмотр позволяет объяснить содержание и навигацию без физического устройства. Он не проверяет системный Mail, реальное прикрепление файла, сохранение черновика и отправку. Эти возможности MessageUI проверяются отдельно в среде, где `canSendMail()` возвращает `true`; подменять результат этой проверки в рабочем приложении не нужно.

## Что настроить разработчику

| Входные данные | Где используются |
|---|---|
| Названия и группы строк | Экран настроек текущего продукта |
| Адрес поддержки и шаблон темы | Письмо и сообщение при недоступной почте |
| Конфигурация чата | Сервис поддержки текущего приложения; реальные значения не попадают в публичные примеры |
| Единый ID аккаунта | Настройки, чат и диагностика письма |
| Версия/build и состояние подписки | Подготовка диагностических полей |
| Генератор очищенного лога | Обязательное вложение письма по `SupportEmail.md` |
| Обработчики открытия, ошибки и закрытия | Навигация, повторное открытие и защита от двойных нажатий |

Экран настроек и подключение поддержки остаются частью приложения. Эта статья показывает примеры; она не добавляет обязательный общий Settings-flow или автоматическую интеграцию Usedesk в платформу.

## Как принять готовую реализацию

1. Откройте настройки без подписки и с активной подпиской. Статус и Premium соответствуют пользователю; текст не скачет после загрузки. Строки подписки открывают пейвол, строки «Cancel subscription» нет, App Store не открывается.
2. Нажмите чат несколько раз подряд. Открывается один экран. Проверьте загрузку, отсутствие сети, клавиатуру, закрытие и повторный вход.
3. Проверьте письмо по `SupportEmail.md`: адрес приложения, установленный build,
   все доступные ID текущего аккаунта, включая ID начисления токенов, и известный
   подтверждённый баланс. Строки `Bundle` нет; очищенный лог прикреплён.
4. Пройдите закрытие и повторное открытие письма. Отмена не считается отправкой, ошибка не выглядит как успех.
5. Проверьте недоступную почту: виден полный адрес, копирование работает, закрытие возвращает в настройки. Неудачный `mailto:` тоже обработан.
6. Проверьте длинные переводы, увеличенный шрифт и небольшой экран. Все строки доступны, нижние кнопки не скрыты; после возврата сохраняется понятное положение списка.
