# Подключение без пароля

Для скачивания четырёх актуальных модулей BroadApps по публичному HTTPS-адресу не нужны аккаунт GitHub, пароль, токен или SDK-ключ. Xcode загружает открытые исходники во время разработки; пользователь установленного приложения не скачивает их из GitHub.

Если Xcode показывает запрос входа, сначала определите, **какой именно адрес он пытается открыть**. Причиной может быть старая ссылка, другая закрытая зависимость, правило Git или состояние сети. Само окно Keychain не доказывает, что виноват BroadCore.

## Сверьте адрес, а не только название

| Product в Xcode | Публичный URL пакета |
|---|---|
| `BroadExtensions` | `https://github.com/BroadApps-official/broad-extensions-ios.git` |
| `BroadCore` | `https://github.com/BroadApps-official/broad-core-ios.git` |
| `BroadMonetization` | `https://github.com/BroadApps-official/broad-monetization-ios.git` |
| `BroadUIFlows` | `https://github.com/BroadApps-official/broad-ui-flows-ios.git` |

`https://github.com/BroadApps-official/BroadCore.git` — старый адрес. Имя Swift-модуля **BroadCore** сохранилось, но актуальный репозиторий называется **broad-core-ios**. Поэтому одного поиска `import BroadCore` недостаточно для проверки подключения.

![В поле Package URL указан полный публичный адрес broad-core-ios](../public/guides/start/xcode-package.png)

## Различайте три вида доступа

| Что просит инструмент | Для чего это бывает нужно | Нужно для первого примера |
|---|---|---|
| Вход в GitHub / Git-ключ | Чтение закрытого репозитория или запись изменений | Нет для чтения публичных модулей |
| Публичный SDK-ключ Adapty | Работа SDK именно вашего приложения | Нет в BroadStart; нужен при подключении своей монетизации |
| Apple Developer Team / подпись | Установка подписанного приложения на устройство и выпуск | Нет для iPhone Simulator |

Не вставляйте пароль GitHub или серверный ключ в Swift-файлы, чтобы исправить загрузку пакета. Это разные механизмы.

## Найдите причину по симптому

| Что видно | Вероятная область проблемы | Следующее действие |
|---|---|---|
| URL содержит старый `BroadApps-official/BroadCore` | Старое подключение приложения | Составить [план миграции](./legacy-app-migration.md), затем переключить нужную группу |
| URL начинается с `git@github.com:` | SSH и его ключи | Для публичного модуля использовать HTTPS; проверить, не переписывает ли его Git |
| Упомянут другой репозиторий | Отдельная зависимость приложения | Проверить доступ именно к нему; не менять BroadCore вслепую |
| Запрос доступа `git-credential-osxkeychain` | Git пытается использовать сохранённые учётные данные | Посмотреть URL и диагностику Git; не удалять всё хранилище паролей |
| `Could not resolve package dependencies` | Общая ошибка выбора или загрузки версии | Прочитать следующую конкретную строку ошибки |
| `No such module` | Product, target, версия iOS или незавершённая загрузка | Проверить [настройки target](./getting-started.md#проверьте-target-и-исходники) |
| `Revision … does not match previously recorded value` | Коммит версии не совпал с ранее запомненным | Выполнить проверку ревизии ниже |
| Таймаут, DNS, ошибка сертификата | Сеть или доверие соединению | Проверить доступ к GitHub; не отключать проверку TLS |

## Проверьте публичный тег без аккаунта

Откройте Terminal и выполните команду из временной папки вне рабочего репозитория. Она читает публичный тег Core **2.1.0**, не скачивает приложение и не удаляет пароли. Глобальные настройки Git и запросы учётных данных отключаются только для этого процесса.

```bash
cd /tmp
GIT_CONFIG_GLOBAL=/dev/null \
GIT_CONFIG_NOSYSTEM=1 \
GIT_TERMINAL_PROMPT=0 \
GIT_ASKPASS=/usr/bin/false \
git -c credential.helper= ls-remote --exit-code \
  https://github.com/BroadApps-official/broad-core-ios.git \
  'refs/tags/2.1.0*'
```

Успех: в выводе есть строки с длинными идентификаторами и `refs/tags/2.1.0`, а запрос входа не появился. Аннотированный тег может дать две строки: сам объект тега и коммит, на который он указывает, с окончанием `^{}`. Это нормально.

| Результат | Вывод |
|---|---|
| Тег прочитан | Публичный адрес доступен этому Terminal; отдельно проверьте проект и настройки Xcode |
| Нет подходящего тега | Проверьте точное написание версии и [каталог](./compatibility.md) |
| Сеть или DNS недоступны | Подключение пакета не исправится вводом SDK-ключа |
| Отказ в доступе | Сверьте полный URL и возможность анонимного чтения; проверьте, не указан ли другой репозиторий |

Не добавляйте `sudo` и не меняйте глобальные настройки ради этой команды. Путь после `cd` означает папку выполнения, а не место, куда устанавливается библиотека.

## Исправьте только подтверждённую причину

Если URL уже правильный, сначала выполните **File → Packages → Resolve Package Versions**. Эта команда выбирает зависимости по действующим правилам проекта. Она отличается от **Update to Latest Package Versions**, которая может обновить версии в разрешённом диапазоне.

Если найдена старая платформа, не удаляйте её до выяснения используемых функций. Одна старая ссылка может предоставлять сразу несколько модулей. Отключение старой группы и добавление новой выполняются согласованно по [инструкции миграции](./legacy-app-migration.md).

**Reset Package Caches** используйте, если есть признаки повреждённого кеша скачивания и исходные адреса уже проверены. Это не универсальное средство от неправильного URL, закрытого репозитория, конфликта версий или изменённого тега. Не удаляйте Package.resolved и всё содержимое Keychain по умолчанию.

После исправления проверьте оба списка: **Project → Package Dependencies** показывает источники, **Target → General → Frameworks, Libraries, and Embedded Content** — библиотеки приложения. Затем соберите и запустите нужный сценарий.

## Если изменилась запомненная ревизия

Сообщение `Revision … does not match previously recorded value` означает, что для одной версии Xcode видит другой коммит, чем записанный ранее. Такую проверку нельзя просто выключить: сначала нужно понять происхождение изменения.

1. Запишите URL пакета, номер версии и оба SHA из ошибки.
2. Сверьте опубликованный тег через `git ls-remote`, релиз GitHub и зафиксированную ревизию проверенного набора.
3. Если сведения расходятся или происхождение неизвестно, остановите обновление этой зависимости и передайте данные владельцу модуля.
4. Если подтверждена устаревшая локальная запись, исправляйте только её, сохранив исходную копию. Это не команда для массовой очистки у всех разработчиков.
5. Повторите подключение со строгой проверкой и сравните новый Package.resolved.

Во время подготовки BroadStart 8 сентября 2026 года найден именно такой случай с локальной записью **BroadExtensions 1.0.1**. Опубликованный тег, релиз и исходники модуля совпали; после адресного исправления записи пример собрался со строгой проверкой. [Фактические результаты](https://github.com/BroadApps-official/broad-docs/blob/main/examples/first-app/Verification.md).

Это описание конкретного найденного случая. Оно не означает, что любое предупреждение о ревизии безопасно игнорировать или что у всех разработчиков есть та же проблема.

## Что передать для диагностики

Достаточно версии Xcode, полного публичного URL, правила версии, имени target и точной строки ошибки. Для ошибки ревизии добавьте два SHA. Не пересылайте пароли, ключи, содержимое Keychain или полный журнал с пользовательскими данными.

Об источниках пакетов: [документация Xcode](https://developer.apple.com/documentation/xcode/adding-package-dependencies-to-your-app). Дальше: [первое подключение](./getting-started.md), [переход со старого BroadCore](./legacy-app-migration.md), [что такое Package.resolved](./glossary.md#xcode-и-подключение).
