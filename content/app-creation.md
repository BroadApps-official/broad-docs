# Создание приложения

Короткий список общих компонентов и команда проверки готового приложения —
в [стандарте приложения](./app-standard.md).

Создать приложение — значит довести конкретный пользовательский путь до результата: человек открывает экран, выполняет действие, получает данные и понимает, что делать при ошибке. Ни установленные пакеты, ни похожий на макет экран по отдельности этого не доказывают.

Ниже разобран работающий **BroadStart**, затем показано, как применять тот же порядок в производственном приложении — вручную или с агентом. [Сначала запустите пример](./getting-started.md), если ещё не видели его на симуляторе.

## Разберите готовый учебный пример

BroadStart — каталог из трёх коротких материалов. У него два экрана: список и выбранный материал. Переключатель внизу позволяет воспроизвести нормальный ответ, пустой список и ошибку. Данные локальные; задержка в 0,8 секунды введена специально, чтобы было видно загрузку.

## Подготовьте входные данные

Для настоящего приложения до написания кода соберите конкретные источники. «Как в другом приложении» — ссылка на пример поведения, а не автоматически подтверждённый сервер, дизайн и условия оплаты.

| Что узнать | Что должно быть на руках | Если этого нет |
|---|---|---|
| Назначение и идентификатор | Задача в Kaiten, имя проекта, Bundle ID | Уточнить у владельца задачи |
| Обязательные экраны | Ссылка на каждый макет и его состояния | Записать отсутствующий экран; не дорисовывать производственный интерфейс по догадке |
| Первый запуск | Состав слайдов, порядок, нужен ли вообще onboarding | Не копировать число страниц из шаблона |
| Данные и действия | Адреса запросов, параметры, пример ответа, правила ошибок и доступа | Остановить только зависящую от них функцию |
| Оплата | Подписка или токены, Adapty, RU Billing, правила Special Offer | Не включать покупку на чужой конфигурации |
| Поддержка и документы | Адрес поддержки, чат при необходимости, Privacy Policy, Terms | Получить значения именно этого приложения |
| Пример поведения | Репозиторий и конкретный экран исходного приложения | Не считать неподтверждённые детали требованиями |

Укажите, какие задачи можно продолжать независимо. Отсутствие одного серверного метода не мешает читать платформу или готовить согласованный экран; оно мешает честно объявить готовой именно эту функцию.

## Запишите короткий план приложения

План лежит в **репозитории приложения**, в `Documentation/AppIntegrationPlan.md`. Он связывает требование с реализацией и проверкой. Если файл уже существует, дополните его; сохраните принятые решения.

Начните с [шаблона плана](https://github.com/BroadApps-official/broad-platform-integration/blob/main/Documentation/Templates/AppIntegrationPlan.md). Пример одной строки:

| Функция | Источник | Данные | Что даёт платформа | Что пишем в приложении | Проверка |
|---|---|---|---|---|---|
| Каталог материалов BroadStart | Учебное задание этой статьи | Три локальных Lesson | Core: состояния и ошибки | Источник, список, экран материала | Список → материал → назад; пусто; ошибка; повтор |

Для каждой производственной функции используйте один из трёх статусов: **READY** — источники известны, **BLOCKED** — не хватает конкретных данных, **N/A** — функция по подтверждённому решению не нужна. Отсутствующие сведения нельзя записать как N/A.

План не хранит секретные ключи и полные ответы с пользовательскими данными. Достаточно ссылки на источник конфигурации, описания полей и безопасного примера.

## Создайте минимальный каркас

Создайте iPhone target, выберите [нужные модули](./module-selection.md) и [подключите их](./getting-started.md). Для BroadStart это Core 2.1.0 и Extensions 1.0.1. Оставьте тексты, модели материалов и дизайн внутри приложения.

```text
Sources/
  BroadStartApp.swift          — создаёт и связывает объекты
  Lesson.swift                — данные и граница источника
  DemoLessonRepository.swift  — локальные учебные ответы
  LessonListModel.swift       — состояние и действия экрана
  LessonListView.swift        — список и экран материала
```

Объекты создаются один раз в `BroadStartApp.init()`. Экраны получают готовую модель; они не создают новый источник данных при каждом пересчёте SwiftUI.

```swift
let repository = DemoLessonRepository()
let loadLessons = LoadLessonsUseCase(repository: repository)
_model = StateObject(
    wrappedValue: LessonListModel(loadLessons: loadLessons)
)
```

Это фрагмент инициализатора из [BroadStartApp.swift](https://github.com/BroadApps-official/broad-docs/blob/main/examples/first-app/Sources/BroadStartApp.swift), а не самостоятельное приложение. Такой способ связывания объектов называют **composition root** — местом сборки зависимостей. Словарь объясняет [эту и другие части архитектуры](./glossary.md#архитектура-и-код).

## Доведите один сценарий до результата

В примере первым сценарием стал **запуск → список → материал → назад**. Его путь через код:

```text
LessonListView: человек нажал «Обновить»
  → LessonListModel: сразу включить загрузку и запретить повтор
  → LoadLessonsUseCase: получить материалы
  → LessonRepository: вернуть список или ошибку
  → LessonListModel: выбрать loaded / empty / stale / error
  → LessonListView: показать результат
```

Состояние загрузки меняется **до создания Task**, а не после первого ответа. Поэтому два быстрых нажатия не успевают создать два запроса.

```swift
guard !state.isLoading else { return }
let previousValue = state.value
state = state.beginLoading()

// Только после этого создаётся Task и выполняется загрузка.
```

Полная обработка результата и отмены находится в [LessonListModel.swift](https://github.com/BroadApps-official/broad-docs/blob/main/examples/first-app/Sources/LessonListModel.swift). Не копируйте только эти три строки вместо всей обработки операции.

Для учебного каталога старые материалы допустимо оставить после ошибки обновления. Для финансового результата это правило не переносится: сохранённый список или кеш не подтверждают покупку и не дают Premium.

## Проверьте все состояния этого сценария

| Ситуация | Что видит человек | Как получить её в BroadStart |
|---|---|---|
| Первая загрузка | Индикатор без ложного пустого экрана | Новый запуск |
| Данные получены | Список, доступные переходы | «Список» |
| Обновление | Список остаётся, кнопка показывает загрузку | Кнопка обновления сверху |
| Успешно, но данных нет | Объяснение пустого результата | «Пусто» |
| Ошибка без данных | Объяснение и повтор | «Пусто» → «Ошибка» |
| Ошибка обновления | Старые материалы и сообщение об ошибке | «Список» → «Ошибка» |
| Повтор | Новая загрузка, затем рабочий список | «Повторить со списком» |
| Возврат с экрана | Список доступен без нового создания сервисов | Материал → назад |

В учебном примере «Ошибка» имитирует отсутствие сети. Это проверка поведения интерфейса с подготовленным ответом, а не доказательство работы настоящего HTTP-клиента. После замены источника отдельно проверяйте фактические ответы своего сервера, ограничения времени ожидания и отмену.

## Как заменить учебные данные настоящими

Сначала согласуйте контракт источника: URL, способ доступа, формат ответа, пустой результат, ошибки, ограничение ожидания. Затем создайте другую реализацию `LessonRepository` и передайте её в `LoadLessonsUseCase` при запуске.

| Слой | Что меняется | Что можно сохранить |
|---|---|---|
| Источник данных | Вместо DemoLessonRepository — реализация своего API | Интерфейс LessonRepository, если договорённость о данных осталась той же |
| Перевод ответа | Модель ответа сервера преобразуется в Lesson | Экран не узнаёт о формате JSON |
| Ошибка | Техническая ошибка преобразуется в безопасный AppError | Текст ошибки и повтор в модели экрана |
| Конфигурация | URL и настройки именно своего приложения | Одно место создания сервисов |
| Интерфейс | Убирается учебный переключатель, добавляется согласованный дизайн | Проверенные переходы загрузки и результата |

Не объявляйте сервер подключённым, пока приложение отвечает из локального массива. Учебные данные полезны для проверки экрана, но должны быть явно обозначены и отделены от производственного источника.

## Если нужны onboarding и оплата

BroadStart специально показывает маленький независимый сценарий. Для расширенного технического примера есть [BroadAppTemplate](https://github.com/BroadApps-official/broad-platform-integration/tree/main/Examples/BroadAppTemplate); он демонстрирует общие механизмы и подготовленные результаты, а не готовый бренд вашего приложения.

| Возможность | Что решить в приложении | Где смотреть реализацию |
|---|---|---|
| Первые слайды | Число, тексты, порядок, нужен ли свой дизайн | [Онбординг: шесть полных проходов](./ui-flows-onboarding.md) |
| Обычная подписка Apple / Adapty | Своё приложение Adapty, ключ, placement, продукты | [Интеграция Adapty](./adapty-integration-guide.md) и [четыре примера paywall](./paywall-ui.md) |
| Второе предложение | Нужно ли оно и как настроен `special_offer` | [Special Offer](./special-offer.md) |
| Карта и СБП | Backend, каталог, условия `ru_pay` и региона, подтверждение результата | [RU Billing](./ru-billing.md) |
| A/B-тест именно RU Billing | Явное подключение tracker, идентификаторы backend и показ варианта | [RU Billing A/B в платформе](./ru-billing-ab-platform.md) |
| Настройки и поддержка | Какие действия, чат или письмо, ссылки и данные приложения | [Настройки и поддержка](./ui-flows-settings-support.md) |

Подключённый модуль не включает эти функции автоматически. Покупка, восстановление, поддержка и ATT имеют собственные условия запуска. Например, ATT допускается после фактического появления первого onboarding-слайда, а не в загрузчике.

## Работа с агентом

Агент работает в папке вашего приложения. Платформа и приложения-примеры служат источниками для чтения; бизнес-логику нельзя незаметно перенести в общий модуль. Для нового проекта используйте [точный стартовый запрос](https://github.com/BroadApps-official/broad-platform-integration/blob/main/Documentation/AgentPreflight.md) и [запросы по этапам](https://github.com/BroadApps-official/broad-platform-integration/blob/main/Documentation/AgentPromptPack.md).

| Этап | Что делает агент | Что проверяет разработчик перед продолжением |
|---|---|---|
| 0. Аудит источников | Читает задачу, дизайн, пример, backend и версии; пока не меняет файлы | Действительно ли найдены нужные источники |
| 1. План | Записывает AppIntegrationPlan без Swift-кода | Границы функций, пробелы, порядок работ |
| 2. Каркас | Создаёт target, подключение, конфигурацию, точки входа | Собирается ли проект, верно ли выбраны зависимости |
| 3. Одна функция | Реализует один согласованный путь со всеми состояниями | Работает ли он целиком; после принятия берётся следующий |
| 4. Функциональная проверка | Проверяет переходы, данные, ошибки и восстановление | Соответствует ли поведение требованиям |
| 5. Проверка внешнего вида | Сравнивает каждый экран с его макетом | Дизайн, маленький и большой iPhone, переходы |
| 6. Передача в QA | Готовит сборки, ограничения и шаги проверки | Что принято, что заблокировано, что проверять QA |

Статусы вида `PLAN REVIEW REQUIRED` означают конкретную остановку для проверки разработчиком. Агент не должен сам себе подтверждать такие этапы. В учебном BroadStart источником поведения служит открытое учебное задание выше; для настоящего приложения это не заменяет материалы вашей задачи.

После паузы агент сначала читает план, последний подтверждённый этап и текущие изменения. Он продолжает незавершённую функцию, сохраняя уже принятые части.

## Работа вручную

Порядок тот же: требования → план → каркас → одна функция → проверка поведения → внешний вид → QA. Отличается исполнитель, а не критерий готовности.

1. Заполните карту экранов и источников данных.
2. Выберите библиотеки по реально используемому API.
3. Соберите пустой проект с этими зависимостями.
4. Реализуйте один путь через модель, операцию и источник данных.
5. Воспроизведите нормальный результат, пустой ответ, ошибку, отмену и повторные нажатия.
6. Сравните экран с его согласованным макетом на маленьком и большом iPhone Simulator.
7. Зафиксируйте принятый результат и переходите к следующей функции.

## Передайте проверяемый результат

| Что приложить к передаче | Зачем это нужно |
|---|---|
| Коммит приложения и Package.resolved | Чтобы повторить ту же сборку |
| Debug / Release Simulator и сборка iphoneos без подписи | Чтобы увидеть различия конфигураций и SDK |
| Короткие шаги для каждого сценария | Чтобы QA воспроизвёл результат без истории переписки |
| Скриншоты или видео состояний | Чтобы было видно поведение и соответствие макету |
| Перечень учебных данных и внешних ограничений | Чтобы локальную демонстрацию не приняли за сервер или настоящую оплату |
| Актуальный AppIntegrationPlan | Чтобы сохранить решения и открытые вопросы |

Проверка платформы подтверждает её модули и технический пример. Она не принимает автоматически приложение разработчика. В автоматических проверках этой платформы не выполняются настоящие покупки, restore и RU-платежи; такой результат нельзя обещать по учебному экрану.
