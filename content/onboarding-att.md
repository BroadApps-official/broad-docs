# Первые экраны и разрешение Apple

У первого запуска три отдельных решения: **какие страницы показать, куда перейти после них и нужен ли запрос на отслеживание**. Количество страниц и содержание определяет приложение. BroadUIFlows управляет переходами, а BroadCore обращается к системному механизму ATT.

ATT — App Tracking Transparency, запрос Apple на разрешение отслеживания. Он не выдаёт доступ к камере, уведомлениям или подписке. Сначала согласуйте, зачем приложению отслеживание; само подключение платформы не требует включать ATT.

## Сначала определите весь маршрут

Запишите не только слайды, но и то, что происходит после последнего. Это нужно до разработки, иначе кнопка «Начать» может вести в никуда или открывать два paywall подряд.

| Решение приложения | Что зафиксировать | Где настраивается |
|---|---|---|
| Нужны ли первые страницы | Да или нет; когда считать их пройденными | `AppFlowConfiguration.onboarding` |
| Какие страницы | Порядок, смысл, заголовок, текст, изображение и действие | `OnboardingConfiguration.pages` |
| Как выглядит экран | Готовая тема или собственная вёрстка | `BroadOnboardingView` или `BroadOnboardingFlowHost` |
| Нужен ли ATT | Назначение запроса и локализованный текст | `trackingAuthorizationPolicy` и Info.plist приложения |
| Нужен ли начальный paywall | Один раз, при каждом холодном запуске или выключен; доступен ли крестик | `AppFlowConfiguration.initialPaywall` |
| Что открывает завершение | Следующий маршрут приложения | Callback `onCompleted` → координатор AppFlow |

Не используйте три страницы BroadAppTemplate как заданное количество. Для примеров дизайна и настоящих проходов откройте [галерею из шести приложений](./ui-flows-onboarding.md). Видео показывает конкретное приложение; общие правила настройки описаны здесь.

## Добавление страницы не требует изменения библиотеки

`pages` — массив всех страниц в нужном порядке. Его длина определяет количество шагов. Для четвёртого слайда добавьте четвёртый элемент; отдельный `slidesCount` не нужен.

Ниже самостоятельный пример конфигурации для BroadUIFlows 1.1.0. Он содержит две учебные страницы и оставляет ATT выключенным. Идентификаторы media здесь соответствуют SF Symbols; renderer должен показать их через `Image(systemName:)`. В реальном проекте это могут быть имена собственных изображений или анимаций.

```swift
import BroadUIFlows

func makeIntroConfiguration() -> OnboardingConfiguration {
    OnboardingConfiguration(
        pages: [
            OnboardingPageConfiguration(
                id: "learn",
                title: "Разберитесь в возможностях",
                subtitle: "Короткие материалы помогут начать.",
                media: OnboardingMediaDescriptor(identifier: "book")
            ),
            OnboardingPageConfiguration(
                id: "practice",
                title: "Попробуйте на примере",
                subtitle: "Откройте материал и выполните первый шаг.",
                media: OnboardingMediaDescriptor(identifier: "hand.tap")
            )
        ],
        continueTitle: "Продолжить",
        completionTitle: "Начать",
        progressAccessibilityLabel: "Шаг знакомства",
        trackingAuthorizationPolicy: .disabled
    )
}
```

`id` должен быть стабильным и уникальным: `learn`, а не случайный UUID при каждом пересчёте экрана. Заголовки и подписи в рабочем приложении берутся из его локализации. Назначение каждого media ID определяет переданный приложением renderer; библиотека не ищет картинку на сервере сама.

## Готовый экран или собственная вёрстка

**Готовый экран:** создайте один `OnboardingViewModel` с конфигурацией и `TrackingAuthorizationUseCaseProtocol`, полученным в точке сборки зависимостей. Передайте его в `BroadOnboardingView`, добавьте renderer `media`, обработчик ссылок `onFooterAction` и `onCompleted`.

**Свой экран:** передайте тот же ViewModel в `BroadOnboardingFlowHost`. Внутри его content-замыкания рисуйте дизайн по `currentPage`, `currentIndex`, `configuration.pages.count` и `isLastPage`. Кнопка продолжения вызывает переданный `actions.advance`.

Host сохраняет общую логику перехода, завершения, видимости окна и ATT. Не держите невидимый `BroadOnboardingView` за своим экраном и не создавайте второй таймер ATT. Контент первого слайда должен действительно быть виден: не накрывайте его собственным полноэкранным loader в момент появления host.

Полные варианты подключения находятся в [OnboardingAndATT.md](https://github.com/BroadApps-official/broad-platform-integration/blob/main/Documentation/OnboardingAndATT.md), а initializer и его параметры — в [BroadOnboardingView.swift](https://github.com/BroadApps-official/broad-ui-flows-ios/blob/1.1.0/Sources/BroadUIFlows/Presentation/Onboarding/BroadOnboardingView.swift).

## Два независимых отключения

Отключить ATT — оставить onboarding, но задать `trackingAuthorizationPolicy: .disabled`. Это значение по умолчанию.

Отключить onboarding — настроить маршрут приложения. Например, эти конфигурации означают разные сценарии:

```swift
import BroadUIFlows

let introWithoutPaywall = AppFlowConfiguration(
    onboarding: .enabled,
    initialPaywall: .disabled
)

let paywallWithoutIntro = AppFlowConfiguration(
    onboarding: .disabled,
    initialPaywall: .onceAfterOnboarding(allowsClose: true)
)

let mainWithoutIntroOrPaywall = AppFlowConfiguration.mainOnly
```

Второй вариант может показать начальный paywall при подтверждённом отсутствии доступа, но первый слайд onboarding в нём не появляется. Поэтому через onboarding ATT не запрашивается. Пустой `pages` не используйте как штатный выключатель.

## Когда система может показать ATT

У Apple есть системные условия: приложение должно быть активно, а другой запрос разрешения не должен ожидать ответа. Уже выбранное разрешение система помнит; повторный вызов не обязан снова показывать окно. Это описано в [документации Apple](https://developer.apple.com/documentation/apptrackingtransparency/attrackingmanager/requesttrackingauthorization%28completionhandler%3A%29).

У BroadApps дополнительно есть своё продуктовое правило: запрос разрешён только после фактического появления **первого** слайда onboarding. Это правило платформы, а не требование Apple размещать ATT именно в onboarding.

Порядок работы общей логики:

1. Onboarding открыт, конфигурация валидна, первый слайд появился и остаётся текущим.
2. Приложение активно; окно прикреплено, видно и не находится в процессе скрытия.
3. Проходит положительная задержка из `.afterFirstSlide(delay:)` — по умолчанию 400 мс.
4. Состояние и реальная видимость окна проверяются повторно; статус должен оставаться `.notDetermined`.
5. Общий use case обращается к системному ATT API.

Задержка не гарантирует появление окна: все условия должны сохраниться. Если человек ушёл со слайда, свернул приложение или onboarding исчез, ожидающая задача отменяется. Loader, bootstrap и создание View не должны самостоятельно запрашивать ATT.

## Что подготовить, если ATT действительно нужен

Включите `OnboardingTrackingAuthorizationPolicy.afterFirstSlide()` в конфигурации страниц. До этого добавьте в target приложения **Privacy - Tracking Usage Description**, техническое имя `NSUserTrackingUsageDescription`. В проекте с генерируемым Info.plist значение задаётся в настройках target; в проекте с отдельным plist — в этом файле.

Напишите короткое конкретное объяснение фактической цели отслеживания и локализуйте его. Не копируйте текст про персонализированную рекламу, если ваше приложение использует данные иначе. Apple требует этот ключ при обращении к ATT API: [назначение и настройка ключа](https://developer.apple.com/documentation/bundleresources/information-property-list/nsusertrackingusagedescription).

Другие системные запросы — уведомления, камера, фото — организуйте отдельно в приложении. Не вызывайте их одновременно с ATT. Общий onboarding не обещает автоматически выстроить очередь всех разрешений вашего приложения.

## Как трактовать ответ

| Статус | Значение | Действие приложения |
|---|---|---|
| `notDetermined` | Решение ещё не получено | Проверить условия показа; отсутствие окна не считать согласием |
| `authorized` | Отслеживание разрешено | Передать разрешённый статус заинтересованному сервису по его контракту |
| `denied` | Пользователь отказал | Продолжить приложение без отслеживания |
| `restricted` | Система ограничивает запрос | Продолжить без попыток заставить окно появиться |

Отказ не должен останавливать onboarding, запрещать кнопку «Начать» или подменяться успехом. ATT и Premium — разные состояния. Системный статус также не является подтверждением согласия на любой другой вид обработки данных.

## Что произойдёт при неправильной конфигурации

Пустой список, одинаковые page ID, пустой заголовок или media ID, неверные подписи действий и повторяющиеся назначения footer-ссылок дают `validationError`. Готовый flow безопасно завершает такой onboarding один раз и не планирует ATT.

Это защита от зависания, а не подтверждение правильной настройки. Перед передачей приложения проверьте `configuration.isValid`, наличие каждого ресурса и весь маршрут. Нулевая или отрицательная задержка ATT переводит policy в `.disabled`, а не вызывает запрос немедленно.

Footer поддерживает политику конфиденциальности, условия и восстановление покупок. Ссылки открывает приложение, восстановление идёт через его платёжный сценарий. **Просьба оценить приложение — Rate Us — внутри onboarding запрещена правилами BroadApps.** Разместить её вне onboarding можно отдельным сценарием.

## Что происходит после последней страницы

`onCompleted` сообщает координатору, что знакомство завершено. Дальше маршрут зависит от конфигурации и подтверждённого доступа:

| Условие | Следующий маршрут |
|---|---|
| Начальный paywall выключен | Главный экран |
| Доступ подтверждён как active | Главный экран с разрешёнными возможностями |
| Доступ подтверждён как inactive и политика требует paywall | Начальный paywall |
| Проверить доступ не удалось — unknown | Бесплатный главный экран; Premium не выдаётся, прохождение paywall не отмечается |
| Одноразовый paywall уже пройден | Главный экран; маркер прохождения не доказывает подписку |

При разрешённом крестике закрытие paywall даёт переход по сценарию приложения. Если подключён Special Offer, сначала завершается его ветка. Нажатие крестика не должно само активировать Premium. ## Проверка перед передачей

| Действие на iPhone Simulator | Ожидаемый результат |
|---|---|
| Пройти 1, 4 и 8 страниц | Завершение только после последней; индикатор соответствует массиву |
| Нажать «Продолжить» сразу на первом слайде | Отложенный ATT не появляется поверх следующего экрана |
| Увести приложение в фон во время задержки | Запрос не появляется в фоне |
| Выключить только ATT | Страницы продолжают работать |
| Выключить onboarding в AppFlow | Страницы и их ATT не появляются |
| Получить отказ ATT | Знакомство и вход в приложение продолжаются |
| Передать неверную конфигурацию в локальном примере | Нет краша и бесконечного пустого экрана; причина доступна для диагностики |
| Пройти последний слайд, paywall и доступные крестики | Открывается ожидаемый главный экран; Premium соответствует проверенному статусу |

На небольшом экране проверьте прокрутку до кнопки и ссылок, длинные тексты и увеличенный размер шрифта. Для состояний разрешения можно использовать подставную реализацию `TrackingAuthorizationRepositoryProtocol`; она проверяет логику, но не доказывает показ настоящего системного окна. Уже сохранённый ответ Apple не надо пытаться сбросить повторными запросами.
