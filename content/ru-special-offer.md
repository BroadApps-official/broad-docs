# RU Billing: Special Offer

Прежде чем добавлять RU-часть, подключите две базовые вещи:

1. **Обычный RU Billing** по статье [«RU Billing: карта и СБП»](./ru-billing.md):
   каталог, `ru_pay`, региональный gate, checkout, возврат из браузера, проверку
   статуса и подтверждение Premium.
2. **Обычный Special Offer от Adapty** по статье
   [«Спешл оффер (от Adapty)»](./special-offer.md): флаг показа, placement и цикл
   окно/cooldown. Начните именно с него — так сам экран, флаг и тайминг уже
   работают на продуктах Adapty.

Ниже описана только RU-добавка: она ничего не меняет в правилах показа, а лишь
переносит источник продукта Special Offer — с Adapty на платёжный каталог
backend.

> **Кратко.** Special Offer — это второй экран после закрытия обычного paywall.
> Он показывается, только когда совпало всё сразу:
>
> - булев флаг показа в Remote Config основного paywall Adapty = `true`;
> - сейчас идёт окно показа, а не cooldown (см. [«Cooldown и окно показа»](#cooldown-и-окно-показа));
> - пользователь закрыл обычный paywall без покупки или restore;
> - у пользователя ещё нет активной подписки.
>
> Если хотя бы одно условие не выполнено — флаг не `true`, поля нет, тип неверный,
> Remote Config не загрузился, идёт cooldown или подписка уже есть — открывается
> главный экран приложения.

## Две независимые настройки

Сценарий держится на двух значениях, у которых разные владельцы. Их нельзя
путать и нельзя заменять одно другим:

| Что | Где | Роль |
|---|---|---|
| Флаг показа | Remote Config основного paywall Adapty | булево значение — разрешает или запрещает экран Special Offer |
| Отметка продукта | платёжный каталог backend приложения | булев признак — помечает, какой RU-продукт показать на этом экране |

Имена ключа и поля зависят от приложения и согласуются с командой — например,
булев флаг `SpecOffer` в Remote Config и булево поле `isSpecialOffer` у продукта
каталога. Их обычно передаёт аккаунт-менеджер вместе с Placement Id и id продукта
Special Offer. RU-продукт **не** приходит из Adapty и **не** выбирается из
App Store: приложение запрашивает платёжный каталог backend по своему bundle ID
и берёт строку с отметкой Special Offer. Её `productId`, рублёвую цену и валюту
экран использует как есть.

> **Откуда берётся продукт.** Флаг Adapty только разрешает показ. Он не выбирает
> продукт и не задаёт цену. Продукт и цена приходят из каталога backend по
> отметке Special Offer. Обычный paywall эту помеченную строку из выдачи
> исключает, чтобы она осталась только для экрана Special Offer.

## Как проходит решение

```text
пользователь закрыл обычный paywall без подтверждённой покупки или restore
                              ↓
             Remote Config основного paywall Adapty
                              ↓
                 булев флаг показа == true?
        ├─ нет / нет поля / конфиг не загрузился / уже есть подписка
        │        → открыть главный экран приложения
        └─ да
              ↓
       в каком состоянии цикл показа (окно оффера / cooldown)?
        ├─ идёт cooldown → открыть главный экран приложения
        └─ окно оффера активно или пора открыть новое окно
              ↓
       запросить платёжный каталог backend по bundle ID приложения
              ↓
       выбрать продукт с отметкой Special Offer
              ↓
       взять его productId, цену и валюту из каталога
              ↓
       передать тот же productId в существующий RU checkout (СБП / карта)
              ↓
     Premium открыть только после подтверждённого backend статуса оплаты
```

Здесь несколько разных владельцев настройки:

| Система | За что отвечает |
|---|---|
| Adapty Remote Config | разрешает или запрещает показ через флаг показа |
| Цикл окно/cooldown | приложение: пока флаг `true`, само чередует окно показа и cooldown |
| Платёжный каталог backend | помечает RU-продукт отметкой Special Offer и отдаёт его `productId`, цену и валюту |
| RU Billing checkout | создаёт оплату для `productId`, полученного из каталога |
| Backend-статус подписки | единственный источник Premium: подтверждает оплату |

Наличие строки каталога само по себе не включает экран. Флаг Adapty не выбирает
продукт. App Store не участвует в выборе RU-продукта. Для рабочего сценария
нужны обе части: флаг показа `true` (и активное окно показа) и строка каталога с
отметкой Special Offer.

## Cooldown и окно показа

Пока флаг показа `true`, показ идёт циклом «окно оффера → cooldown»:

- при первом подходящем закрытии paywall открывается **окно оффера** (в текущей
  реализации — 24 часа). Внутри окна Special Offer появляется при каждом
  подходящем закрытии;
- когда окно истекает, начинается **cooldown** такой же длительности (24 часа),
  отсчитываемый от конца окна. В cooldown оффер не показывается, даже если флаг
  всё ещё `true`;
- после окончания cooldown цикл повторяется: при следующем подходящем закрытии
  открывается новое окно оффера.

Цикл продвигается только по событиям закрытия paywall — фонового таймера нет.
Окно и cooldown материализуются в момент, когда пользователь закрывает paywall.

Обратный отсчёт на экране Special Offer показывает время до конца текущего окна
оффера — это та же дата, по которой принимает решение gate. Когда счётчик
доходит до нуля, экран закрывается и начинается cooldown. Это уже не
косметический таймер, который просто перезапускается.

Состояние сбрасывается к начальному в трёх случаях:

- **флаг показа выключили** в Adapty — сбрасываются и окно оффера, и
  незавершённый cooldown; после повторного включения цикл стартует заново с
  нового окна при следующем закрытии paywall;
- **покупка подтверждена** — цикл сбрасывается;
- **часы устройства перевели назад** — состояние сбрасывается, чтобы cooldown
  нельзя было обойти.

Храните окно и cooldown как даты в постоянном хранилище приложения. Не заводите
для них отдельный серверный таймер или server-driven дату окончания, если этого
нет в отдельном продуктовом требовании.

## Что настроить в Adapty

Добавьте в Remote Config основного paywall булев флаг показа. Точное имя ключа
согласуйте с командой, например:

```json
{
  "SpecOffer": true
}
```

Приложение принимает булево `true`, а также его эквиваленты (число `1` или
строку `"true"`). Не заводите отдельный локальный флаг в приложении. Решение
принимается по текущему фактически полученному Remote Config; если конфиг ещё не
успел прийти к моменту закрытия paywall, приложение делает вынужденное обновление
и только потом решает.

Выключение флага не просто прячет экран: оно сбрасывает цикл окно/cooldown к
начальному состоянию (см. [«Cooldown и окно показа»](#cooldown-и-окно-показа)).

На этом роль Adapty в выборе RU-продукта заканчивается: он передаёт gate показа,
но не продукт и не рублёвую цену. Не ищите RU-продукт Special Offer в Adapty или
App Store.

## Что должно быть в платёжном каталоге backend

Приложение запрашивает свой платёжный каталог backend существующим
авторизованным клиентом (тем же, что в основной статье RU Billing) и передаёт
свой bundle ID. Не публикуйте учётные данные каталога и не вшивайте их в общий
package.

В ответе для этого bundle ID строка Special Offer должна:

- иметь отметку Special Offer (булев признак, по которому она и выбирается);
- быть подписочной, если оффер подписочный;
- содержать `productId`, цену и валюту.

Отметку в каталоге проставляет тот, кто ведёт RU-админку (по согласованному id
продукта). Приложение не выбирает самый дешёвый или первый тариф и не начинает с
Adapty/App Store SKU. Оно берёт из каталога именно строку с отметкой Special
Offer. Если такой строки нет, подставлять обычный тариф нельзя — экран остаётся
без продукта.

## Что передать в RU Billing checkout

RU checkout должен принимать продукт, который вернул каталог backend:

```text
Код продукта: <productId из каталога>
Цена:          <цена и валюта из каталога>
Статус:        активен
```

Код не выбирается и не сопоставляется через Adapty или App Store. Истина для
RU Special Offer — строка платёжного каталога backend; её `productId`
передаётся в checkout без подмены по цене, позиции или похожему названию.

Не копируйте app-level переключатель «сделать все продукты разовыми» как часть
Special Offer: тип оплаты задаётся базовой настройкой RU Billing конкретного
приложения.

## Что добавить в приложение

1. После закрытия обычного paywall убедитесь, что purchase и restore не
   подтвердили Premium.
2. Прочитайте флаг показа из текущего Remote Config основного paywall.
3. Если значение не приводится к булеву `true`, конфиг не загрузился или у
   пользователя уже есть активная подписка — откройте главный экран приложения.
4. Проверьте цикл показа: если идёт cooldown — откройте главный экран; если окно
   оффера активно или пора открыть новое окно — продолжайте.
5. При открытии нового окна застолбите его конец (например, `now + 24h`); когда
   окно истечёт, застолбите cooldown (конец окна `+ 24h`).
6. Запросите каталог backend по bundle ID приложения и найдите продукт с отметкой
   Special Offer (в обычном paywall эта строка исключается).
7. Передайте его `productId` в уже реализованный checkout из основной статьи
   RU Billing.
8. Сбрасывайте цикл при выключении флага, при подтверждённой покупке и при
   переводе часов назад.
9. После возврата из браузера проверьте статус на backend. Сам возврат из
   браузера не означает успешную оплату.

Источник RU-продукта в этом сценарии — только платёжный каталог backend
приложения. Не используйте для его выбора Adapty, App Store или прежние
маршруты продуктов.

## Что проверить без настоящей оплаты

| Проверка | Ожидаемый результат |
|---|---|
| флаг показа = `true`, окно оффера активно | Special Offer открывается |
| повторное закрытие paywall внутри окна оффера | Special Offer открывается снова |
| окно оффера истекло | начинается cooldown, оффер не показывается |
| внутри cooldown, флаг всё ещё `true` | Special Offer не показывается |
| cooldown закончился | при следующем закрытии открывается новое окно оффера |
| флаг выключили, затем снова включили | цикл сброшен, открывается новое окно |
| часы устройства перевели назад | состояние сброшено, cooldown обойти нельзя |
| флаг = `false` или поля нет | открывается главный экран приложения |
| Remote Config ещё не загрузился | показ не срабатывает по ошибке; после обновления конфига решение принимается заново |
| у пользователя активная подписка | Special Offer не показывается |
| в каталоге backend нет строки с отметкой Special Offer | обычный тариф из Adapty или App Store не подставляется |
| каталог backend вернул помеченный продукт | его `productId` без подмены передаётся в RU checkout |
| пользователь вернулся из браузера без подтверждения | Premium не открывается |
| backend подтвердил активную оплату | Premium открывается |

## Задание для Codex или Claude

```text
Сначала подключи обычный RU Billing строго по статье «RU Billing: карта и СБП».
Не дублируй checkout, browser return, проверку статуса и подтверждение Premium.

Реализуй RU Billing Special Offer:
- флаг показа: булево поле в Remote Config основного paywall
  (имя согласовано с командой, например SpecOffer); принимай bool и его
  эквиваленты (1, "true");
- источник RU-продукта: платёжный каталог backend приложения по его bundle ID;
- выбирай продукт по отметке Special Offer в каталоге (например, булево поле
  isSpecialOffer), не по цене, позиции или названию;
- productId, цену и валюту бери из этой строки каталога;
- в обычном paywall помеченный продукт исключай из выдачи.

Показ ограничь циклом окно оффера -> cooldown:
- пока флаг true, при первом подходящем закрытии paywall открывай окно оффера
  (24 часа); внутри окна показывай Special Offer при каждом подходящем закрытии;
- когда окно истекло, стартуй cooldown такой же длительности (24 часа) от конца
  окна; внутри cooldown не показывай оффер, даже если флаг true;
- после cooldown цикл повторяется новым окном;
- окно и cooldown храни как даты; продвигай цикл по событиям закрытия paywall.
Обратный отсчёт на экране веди до конца окна оффера; на нуле закрывай экран и
стартуй cooldown. Сбрасывай состояние при выключении флага, при подтверждённой
покупке и при переводе часов назад.

После закрытия обычного paywall без подтверждённой покупки или restore:
показывай Special Offer только если флаг == true и цикл в окне показа; иначе
(false, незагруженный конфиг, активная подписка, идущий cooldown) открывай
главный экран.

Не бери RU-продукт из Adapty или App Store и не выбирай его по цене, позиции
или похожему названию. Передай productId строки каталога в существующий
RU checkout. Возврат из браузера не считай оплатой; Premium открывай только
после подтверждения backend. Настоящий платёж не выполняй.
```
